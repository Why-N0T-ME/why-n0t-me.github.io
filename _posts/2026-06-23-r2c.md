## ret2csu란 무엇인가

`ret2csu`는 64비트 환경에서 ROP Chain을 구성할 때 **`pop rdi` 외에
`rsi`, `rdx` 등의 레지스터를 세팅할 가젯이 없을 때** 사용하는 기법이다.

64비트 바이너리에는 C 런타임 초기화 함수인 `__libc_csu_init`이 컴파일러에 의해
자동으로 삽입되는데, 이 함수 안에 `rdi`, `rsi`, `rdx`를 한번에 세팅할 수 있는
가젯이 숨어있다. 바이너리에 항상 존재하는 코드이므로 ASLR/PIE와 무관하게
(PIE 꺼진 환경에서) 고정 주소로 사용할 수 있다는 것이 핵심이다.

## __libc_csu_init 구조

`__libc_csu_init`의 끝부분에는 다음과 같은 패턴의 코드가 존재한다.

```asm
; 가젯 2 (gadget 2) - 먼저 이 가젯으로 레지스터 초기값 세팅
pop rbx        ; 0으로 세팅
pop rbp        ; 1로 세팅 (루프 조건용)
pop r12        ; 호출할 함수 주소
pop r13        ; rdx로 복사될 값 (제3 인자)
pop r14        ; rsi로 복사될 값 (제2 인자)
pop r15        ; edi로 복사될 값 (제1 인자 하위 32bit)
ret

; 가젯 1 (gadget 1) - 위에서 세팅한 값을 실제 레지스터에 복사
mov rdx, r13
mov rsi, r14
mov edi, r15d
call qword ptr [r12 + rbx*8]  ; 함수 호출
```

공격자는 **가젯 2 → 가젯 1** 순서로 체인을 구성한다.
```
[가젯 2 주소      ]  ← 반환 주소 덮어쓰기
[rbx = 0         ]  ← pop rbx
[rbp = 1         ]  ← pop rbp (루프 탈출 조건)
[r12 = func_addr ]  ← pop r12 (호출할 함수 주소)
[r13 = rdx 값    ]  ← pop r13 (제3 인자)
[r14 = rsi 값    ]  ← pop r14 (제2 인자)
[r15 = rdi 값    ]  ← pop r15 (제1 인자)
[가젯 1 주소      ]  ← ret 후 가젯 1로 이동
[dummy * 7       ]  ← 가젯 1 내부 pop들 처리용 패딩
[다음 체인        ]
```

> **주의**: `r15d → edi` 복사이므로 `rdi` 상위 32비트는 0으로 클리어된다.
> 주소값처럼 상위 비트가 필요한 경우 별도 처리가 필요하다.

## ROP Chain에서의 위치

ret2csu는 단독 공격이라기보다 **ROP Chain 중간에 레지스터 세팅 수단**으로 쓰인다.
```
[offset 패딩           ]
[가젯 2 주소           ]  ← rdi/rsi/rdx 세팅 시작
[rbx, rbp, r12 ~ r15  ]
[가젯 1 주소           ]  ← 실제 레지스터에 값 복사 + 함수 호출
[dummy * 7             ]
[pop rdi; ret          ]  ← rdi 보정이 필요한 경우
["/bin/sh" 주소        ]
[system() 주소         ]  ← 최종 목표
```

## 트러블슈팅: 최신 gcc에서 __libc_csu_init이 사라졌다

### 증상

![ifunc](/assets/img/posts/r2c/ifunc.png)
```bash
pwndbg> i func
# __libc_csu_init이 목록에 없음

objdump -d ./vuln | grep -A 30 "libc_csu_init"
# 아무것도 출력되지 않음
```

### 원인

`__libc_csu_init`은 **gcc 12 / glibc 2.34** 버전을 기점으로 제거되었다.

기존에 `__libc_csu_init`이 담당하던 C 런타임 초기화 역할이
glibc 내부로 흡수되면서 바이너리에 더 이상 삽입되지 않는다.

| glibc 버전 | __libc_csu_init |
| --- | --- |
| 2.33 이하 | 바이너리에 포함됨 |
| 2.34 이상 | **제거됨** |

```bash
# glibc 버전 확인
ldd --version
```

### 대안

`__libc_csu_init`을 사용할 수 없는 환경에서는 다음 방법을 고려한다.

| 방법 | 설명 |
| --- | --- |
| **libc 가젯 사용** | libc 내부의 `pop rsi`, `pop rdx` 가젯 활용. libc leak이 선행되어야 함 |
| **FSOP** | FILE 구조체를 조작해 임의 함수 실행. glibc 2.34+ 환경의 대표적 대안 |
| **SigReturn ROP (SROP)** | `sigreturn` 시스템 콜로 레지스터 전체를 한번에 세팅 |
| **one_gadget** | libc 내에 조건만 맞으면 바로 셸을 주는 원샷 가젯 |

> 현대 익스플로잇 환경에서 ret2csu는 사실상 레거시 기법이 되었다.
> 다만 구버전 바이너리나 CTF 문제에서는 여전히 자주 등장하므로
> 원리를 이해해두는 것이 중요하다.

## RTL / ROP / ret2csu 관계 정리

세 기법은 모두 NX 우회를 목표로 하지만 **재사용하는 대상**이 다르다.

| 기법 | 재사용 대상 | 목적 |
| --- | --- | --- |
| **RTL** | libc 함수 자체 (`system()` 등) | 함수를 직접 **실행** |
| **ROP** | 함수 내 코드 조각 (가젯) | 레지스터 세팅 + 함수 실행 |
| **ret2csu** | libc 준비 함수(`__libc_csu_init`) 내 가젯 | 가젯 부족 시 **레지스터 세팅** 수단 |

ret2csu는 독립적인 공격 기법이 아니라 **ROP의 하위 기법**이다.
가젯이 부족한 환경에서 `__libc_csu_init` 안의 가젯으로 레지스터를 세팅한 뒤,
최종적으로는 RTL처럼 libc 함수를 호출하는 것이 목표다.

```
ret2csu로 rdi/rsi/rdx 세팅    ← 준비 단계 (ROP)
→ system("/bin/sh") 호출      ← 최종 실행 단계 (RTL)
→ 셸 획득
```

정리하면 **RTL이 최종 목적지**이고, **ROP/ret2csu는 그 목적지까지 가기 위한 수단**이다.
