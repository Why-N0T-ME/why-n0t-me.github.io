## 개념
### **퍼징이란?**
**퍼징(Fuzzing)**은 프로그램에 무작위(random)하거나 예상치 못한 입력값을 자동으로 대량 주입해서, 크래시(crash)·에러·예외 등 비정상적인 동작을 찾아내는 자동화된 취약점 탐색 기법이다. (프로그램에 이상한 값을 수백만번 넣어서 어떻게 반응하는지 시험하는것이라고 생각하면 쉽다.)

### **퍼저란?**
퍼저는 퍼징을 수행하는 도구로 *AFL, libFuzzer, OSS-Fuzz, Peach Fuzzer*같은 도구들이 있다.

*퍼징을 사용하는 이유*
1. 자동화: 테스트 케이스를 일일이 만들지 않아도 된다
2. 규모: 수백만건의 입력을 단시간에 시험하는것이 가능하다
3. 취약점 발견: 개발자가 생각하지 못한 케이스를 발견할수 있다
4. 비용 효율: 바이너리만 있다면 테스트 가능하다

## 퍼저의 유형
### 블랙박스 퍼저 (Blackbox Fuzzer)
* Def: 프로그램의 내부 구조를 전혀 알지 못하는 상태에서 입력을 던지는 방식
* pros: 구현이 단순 & 어떤 타켓이든 적용이 가능
* cons: 무작위성이 높기때문에 효율이 낮음
* example: 네트워크 프로토콜 서버에 무작위 패킷을 전송

### 화이트박스 퍼저 (Whitebox Fuzzer)
* Def: 소스코드나 프로그램의 내부 로직을 분석한 후에 입력을 생성하는 방식, **Symbollic Execution**을 활용해 특정 코드 경로를 정확하게 커버하는 입력을 만들어낸다.
* pros: 깊은 코드 경로까지 도달이 가능하여 정확도가 높음
* cons: 구현이 복잡하며 대형 프로그램에서 속도가 느려짐
* example: KLEE, SAGE

### 그레이박스 퍼저 (Greybox Fuzzer)
* Def: 프로그램을 계측하여 코드 커버리지 정보를 피드백으로 받아, 더 많은 코드 경로를 탐색하는 방향으로 입력을 진화시킨다. 프로그램을 계측한다는건 *프로그램 실행시 내부경로 정보를 실시간으로 수집*할수 있도록 코드를 삽입하는 과정을 말한다.

* pros: 블랙박스보다 효율적이며 화이트박스보다 빠름
* cons: 컴파일 시 계측 코드 삽입이 필요함 (소스코드 or 바이너리 계측)
* example: AFL++, libFuzzer, Honggfuz

```sh
구분:           내부정보        소스코드    속도
화이트박스:      전체분석        필요       느림
블랙박스:        없음           불필요     빠름
그레이박스:      커버리지        필요       빠름
```

## Sanitizer - 메모리 오류, 버그 감지 도구
Sanitizer - 컴파일 시 코드에 검사 로직을 심어서, 실행 중 버그를 실시간으로 감지해주는 도구로 원래 크래시가 안 나고 조용히 넘어가는 버그를 크래시로 만들어서 퍼저가 발견할 수 있게 함

**세니타이저의 역할**
1. 메모리 오류 감지 - 버퍼 오버플로우, 해제된 메모리 사용(Use-After-Free) 등 치명적인 메모리 접근 오류를 실시간으로 잡음
2. 취약점 조기 발견 - 일반적인 실행에서는 문제없이 넘어가거나 나중에 큰 보안 위협이 될 수 있는 정의되지 않은 동작(Undefined Behavior)을 탐지
3. 상세한 로그 제공 - 오류 발생 시 프로그램의 스택 트레이스(Stack Trace)와 상세한 문제 위치를 기록

**세니타이저의 종류**
```txt
ASan - 가장 대표적인 세니타이저, 버퍼 오버플로우, Use-After-Free(해제된 메모리 재사용), 힙/스택 오버플로우
UBSan - C/C++ 표준에서 정의하지 않은 동작(정수 오버플로우, NULL 포인터 역참조, 0으로 나누기)을 탐지
MSan - 초기화되지 않은 메모리 값을 읽는 동작을 추적

사용시 -fsanitize=address 플래그 추가
*퍼징 과정에서 세니타이저를 함께 사용하면 탐지율이 크게 향상되며, 주로 C/C++ 기반의 시스템 소프트웨어나 브라우저 엔진 등을 테스트할 때 필수적으로 활용한다.
```

## 퍼징의 동작 원리: 파이프라인
퍼징은 5개의 단계가 반복되는 피드백 루프이며 다음처럼 동작한다.
```txt
[1]시드 입력 준비 -> 
[2]입력 변형(Mutation) -> 
[3]타겟 프로그램 실행 -> 
[4]실행 결과 모니터링 -> 
[5]크래시 저장 / 커버리지 피드백 -> 
[2]
```
{: file="step.txt"}

1. **시드(Seed)준비**
시드는 퍼저가 처음 변형의 재료로 사용하는 초기 입력값이다. 예를들어 이미지 파싱 프로그램이면 정상적인 PNG파일 몇 개가 시드가 된다.
2. **입력 변형(Mutation)**
퍼저는 시드를 다양하게 변형해 새로운 테스트케이스를 만들어낸다.
```
Bit Flip - 특정 비트를 바꾼다. (0 -> 1, 1 -> 0)
바이트 교체: 랜덤한 바이트로 치환
경계값 삽입: INT_MAX, 255,0, -1 같은 경계값을 주입
블록 삭제/복제: 입력의 일부를 지우거나 반복
Splicing: 두 시드를 합쳐서 새로운 입력을 생성
```
3. **Target 실행**
변형된 입력을 프로그램에 주입하여 실행한다.
4. **실행 결과 모니터링**
실행 후 `크래시, 타임아웃, 새로운 커버리지`가 발생했는지 확인

```
Crash: Segfault, Stack overflow, Heap corruption etc.
timeout: 무한루프 등
새로운 커버리지: 이전에 도달하지 못했던 코드 경로를 발견
```

퍼징을 실행하면 결과디렉터리에 `carshes, hangs, queue`하위 디렉터리가 생성된다.
```sh
crashes/
프로그램이 비정상 종료된 경우 저장되며 시그널 종류가 파일에 표시된다.
크래시를 유발한 입력으로 직접 실행할수 있고 어떤 입력이었는지 확인도 가능하다.

hangs/
타임아웃이 설정된 시간 안에 종료되지 않을경우 저장되며 *무한루프, 교착상태* 등이 원인이다.

queue/
크래시는 아니지만 이전에 밟지 못한 코드 경로를 발견한 입력을 저장하여 이 입력들을 집중적으로 변형해 더 깊은 경로를 탐색
```
{: outcome}

5. **피드백&시드 업데이트**
새로운 코드 경로를 발견하면 이를 발견한 입력을 *시드 큐(Seed Queue)*에 추가하고 이후 변형의 재료가 된다. 피드백 루프로 더 깊은 코드 경로까지 탐색을 함

### 용어 정리
```
Seed        -퍼저가 변형의 재료로 사용하는 초기 입력값
Mutation    -시드를 변형해 새로운 테스트케이스를 생성하는 과정
Corpus      -퍼징에 사용하는 시드들의 집합
Coverage    -퍼징 중 실행된 코드의 비율 (branch/edge 단위)
Crash       -프로그램이 비정상 종료되는 것 (취약점의 증거)
Sanitizer   -메모리 오류를 감지하는 도구 (ASan, UBSan 등)
Harness     -퍼저가 타겟 함수를 반복 호출하도록 감싸는 래퍼 코드(특정 함수나 라이브러리만 반복 호출)
Triage      -발견된 크래시를 분류하고 우선순위를 정하는 과정
```

## 실습(With WSL-Window Subsystem for Linux)
AFL++(Greybox Fuzzer)를 이용한 간단한 퍼징 실습
*타겟 프로그램 - 파일을 열어 내용을 읽고(buf) 종료하는 프로그램*
```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

int main(int argc, char *argv[]) {
    char buf[64];
    FILE *f = fopen(argv[1], "r");
    if (!f) return 1;
    fread(buf, 1, 63, f);
    fclose(f);

    if (buf[0] == 'F') {
        int *p = NULL;
        *p = 42;  // crash!
    }
    return 0;
}
```

```sh
sudo apt-get install afl++

git clone https://github.com/AFLplusplus/AFLplusplus
```
{:file="AFL++ 설치"}

C언어를 실행 가능한 파일을 만들때 gcc를 흔히 사용하지만, 그렇게 하면 그냥 실행만 된다. 우리는 계측을 삽입홰서 프로그램을 퍼징할때 어떤 branch를 새로 밟았는지 알아야 하므로 AFL++ 전용 컴파일러로 캄파일을 한 후 퍼징을 실행할 것이다. (계측이 없으면 무작위로 변형만 반복한다.)
*블랙박스는 실행 결과로 정상/크래시 구분만 가능하고 다음 입력을 무작위로 만들어내지만, 그레이박스는 계측을 통해 실행마다 커버리지 정보를 피드백으로 활용한다.*

```sh
# ASan 포함해서 컴파일, UBSan을 같이 사용할시 `,undefined`를 추가하면 된다.
afl-cc -fsanitize=address -o target target.c
```
{: file="compile.sh"}

![compile](/assets/img/posts/fuzzing/compile.png)

```sh
afl-fuzz -i seeds/ -o findings/ -- ./target @@

-i seeds/ : 시드입력 디렉토리
-o findings : 결과저장 디렉토리
-- : AFL++ 옵션의 끝
./target : 퍼징할 타겟 프로그램
./target @@ : 타겟이 입력을 file로 받을때 사용
```
