## Concept
What is CSRF??
We've learned basic XSS with Dreamhack wargme(xss-1, xss-2).Otherwise XSS is client-side vulnerability, CSRF is Server-side vulnerability.
Attacker can make users who has done authentication send requests never their intent. like deleting,creating, modifying resources.

key Difference
XSS     : script runs on the browser 
CSRF    : user request evil script from server

### 문제

### 기능분석

```python
@app.route("/vuln")
def vuln():
    param = request.args.get("param", "").lower()
    xss_filter = ["frame", "script", "on"]
    for _ in xss_filter:
        param = param.replace(_, "*")
    return param
```
{: file="vuln.py"}
/vuln를 보면 xss_filter에서 `frame`, `script`, `on`을 *로 필터링하기 때문에 XSS은 사용할 수 없으므로 CSRF 공격을 써야함을 유추할 수 있다.

```python
@app.route("/admin/notice_flag")
def admin_notice_flag():
    global memo_text
    if request.remote_addr != "127.0.0.1":
        return "Access Denied"
    if request.args.get("userid", "") != "admin":
        return "Access Denied 2"
    memo_text += f"[Notice] flag is {FLAG}\n"
    return "Ok"
```
{: file="flag-is-here.py"}
해당 페이지에 접근하는 유저가 로컬호스트이고 userid가 admin이면 memo_text에 플레그값을 누적하여 Ok를 반환한다.
즉, userid=admin인 유저가 /admin/notice_flag로 이동하도록 하는 페이로드를 작성하여 보내면 된다.

### 익스플로잇

/flag 페이지에서 ?param값에 CSRF 공격 페이로드를 작성하여 보낸다.
```html
<img src="/admin/notice_flag?userid=admin">
```

## CSRF2
### 서비스 분석
CSRF2 문제는 로그인과 비밀번호 변경 기능이 구현되어있다.
코드에서 확인할수 있는 엔드포인트는 `/vuln`, `/flag`, `/login`, `/change_password` 가 있다.

1. `/vuln`페이지에서 xss_filter로 XSS에 사용할수 있는 태그를 필터링 하기에 XSS을 사용할순 없어 보인다.
```python
xss_filter = ["frame", "script", "on"]
    for _ in xss_filter:
        param = param.replace(_, "*")
```
{: file="vuln.py"}

2. `/login` 페이지는 아이디와 패스워드를 입력받아서 [아이디]의 값과 pw의 값이 같으면 인증을 진행한다.
username: guest, password: guest로 guest계정에 로그인에 성공할수 있다.

```python
@app.route("/change_password")
def change_password():
    pw = request.args.get("pw", "")
    session_id = request.cookies.get('sessionid', None)
    try:
        username = session_storage[session_id]
    except KeyError:
        return render_template('index.html', text='please login')

    users[username] = pw
    return 'Done'
```
{: file="core.py"}
3. `/change_password` 페이지가 이번 문제의 핵심이다. 해당 엔드포인트는 pw를 파라미터값으로 받아 현재 세션아이디에 해당하는 계정의 비밀번호를 pw로 변경한다.
따라서, 어드민이 /change_password?pw={공격자가 원하는 값} 처럼 요청을 보내게 하면 공격자가 원하는대로 어드민의 비밀번호를 조작하고 로그인할 수 있을것이다.

```python
def check_csrf(param, cookie={"name": "name", "value": "value"}):
    url = f"http://127.0.0.1:8000/vuln?param={urllib.parse.quote(param)}"
    return read_url(url, cookie)
```
{: file="bot.py"}
4. check_csrf함수를 보면 /vuln?param=(param) 요청을 보낸다. 즉 우리가 `/flag`탭에서 페이로드를 제작하여 보내면 봇이 자동으로 우리의 페이로드를 열어보고 패스워드를 변경하게 된다.

### 익스플로잇
```html
<img src="/change_password?pw=p123">
```
{: payload.html}
이처럼 페이로드를 보내면 pw값인 p123이 /change_passwd 경로로 파라미터값으로 들어가고 이때 어드민의 세션아이디가 같이 붙어서 나가기 때문에 비밀번호 변경에 성공하게 되고 이후엔 간단히 id, pw를 입력하여 어드민계정으로 로그인하면 된다.
