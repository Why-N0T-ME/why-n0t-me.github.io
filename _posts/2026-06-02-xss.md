## Concept?
**XSS**은 웹페이지에 악성 스크립트를 삽입하여 의도치않은 동작을 수행하게 하는 공격기법이다. HTML에는 <script></script>태그가 있고 이 태그 안쪽에 있는 **JavaScript** 코드가 DOM을 조작하는데 사용자가 입력할수 있는 필드가 존재할때 이에 JS가 실행될 수 있도록 HTML태그를 삽입하여 웹 어플리케이션 개발자가 의도한 동작이 아닌 악성 행위를 동작하는 공격이다.

**XSS의 유형**
1. **Stored XSS** - 악성 스크립트가 서버의 DB나 파일 시스템에 저장되어 클라이언트가 이에 접근하여 요청시 스크립트 실행
    *attack flow*: 공격자가 XSS에 취약한 게시판의 글이나 댓글 등에 악성 스크립트를 포함시켜 업로드하고 이를 일반 사용자가 조회하면 서버에서 해당 스크립트가 브라우저로 전달되어 실행됨.
2. **Reflected XSS** - 서버가 사용자의 입력값(URL parameter, input)을 받아 검증없이 응답 페이지에 즉시 reflect하여 브라우저에서 실행
    *attack flow*: 공격자가 악성 스크립트가 포함된 URL을 생성하여 피싱(이메일, 메신저, sns등)을 이용해 사용자가 해당 링크를 클릭하게 유도. 링크를 클릭시 스크립트가 실행.
3. **DOM based XSS** - 서버응답에는 악성 스크립트가 포함되지 않지만, 클라이언트 측 JScode의 결함으로 인해 DOM을 처리하는 과정에 발생
    *attack flow*: 브라우저의 URL Fragment나 사용자 입력값을 클라이언트 측 스크립트가 읽어와 페이지에 동적반영할때 발생.
    fatal한 fragment가 포함된 url에 접속 -> frontend 코드의 부주의한 돔 조작으로 evil script 실행.


## 서비스 분석
### 문제
XSS문제는 XSS-1과 XSS-2 두가지가 있다. 두 문제 모두 **Reflected XSS**(URL에 JS가 삽입되어 XSS에 취약)를 이용해 문제를 풀어야 한다. 우선 필자는 두 문제를 굳이 따로 정리하진 않을것임을 밝힌다. 후에 기술할 것이지만 두 문제 모두 필터링과 이스케이프 처리가 없는 XSS문제라는 점에서 사실상 같은 문제라 봐도 되기 때문이다.
### 기능분석
XSS-1과 XSS-2 문제 둘다 필터링과 이스케이프 처리가 없어 *XSS에 취약한 서비스*이다. 그리고 두 서비스 모두 `/vuln`, `/flag`, `/memo` 엔드포인트를 가지고 있으며 세개 모두 거의 같은 기능을 한다. 다만, 차이가 없는것은 아니다. XSS-2는 *innetHTML을 사용*하기 때문에 **<scrript></script>태그가 작동하지 않는다**. (W3C HTML5 명세에 따라, innerHTML을 통해 삽입된 script태그는 보안상의 이유로 동작하지 않는다고 한다.)

각 엔드포인트를 살펴보자. (XSS-2 기준으로 문제를 풀면 두 문제 모두 풀리기에 XSS-2를 기준으로 살펴보겠다)
1. `/vuln`
```python

@app.route("/vuln")
def vuln():
    return render_template("vuln.html")

```
{: file="endpoint.py"}

`/vuln`페이지는 vuln.html을 가져와서 reder_template을 사용하여 동적 데이터를 넣은 최종 HTML코드를 완성하여 반환한다.
2. `/flag`
```python

@app.route("/flag", methods=["GET", "POST"])
def flag():
    if request.method == "GET":
        return render_template("flag.html")
    elif request.method == "POST":
        param = request.form.get("param")
        if not check_xss(param, {"name": "flag", "value": FLAG.strip()}):
            return '<script>alert("wrong??");history.go(-1);</script>'

        return '<script>alert("good");history.go(-1);</script>'

```
{: file="endpoint.py"}

`/flag`는 사용자의 요청 메소드에 따라 동작이 달라지는데, `GET`요청을 받으면 flag.html을 반환하고 `POST`면 <script>를 리턴함. param값에 사용자 입력이 들어감. 이 param값이 필터링이나 이스케이프 없이 vuln.html에서 렌더링되므로 XSS취약점을 이용할수 있다.
3. `/memo`
'''python

memo_text = ""
@app.route("/memo")
def memo():
    global memo_text
    text = request.args.get("memo", "")
    memo_text += text + "\n"
    return render_template("memo.html", memo=memo_text)

'''
{: file="endpoint.py"}

`/memo`는 입력으로 받아 memo_text에 누적시키고 이를 파라미터 ?memo에 넣어서 memo.html을 반환한다.
### 익스플로잇

결국 XSS-1, XSS-2 모두 `/flag`에서 사용자의 입력값을 받는 파라미터 param=[입력값]에 JS가 실행되도록 HTML태그를 주입하여 cookie값을 `/memo`에 출력되게 하면 된다. 두 문제 모두 <img src=x onerror="fetch('/memo?memo='+document.cookie);"> 를 주입하면 플래그를 얻을수 있다. 물론, XSS-1 문제는 script태그가 작동하기 때문에 <script>location.href="/memo?memo="+document.cookie</script> 처럼 페이로드를 작성해도 FLAG를 얻을수 있을 것이다.
