## Concept
`chall3.exe`는 사용자 입력값을 특정 수식(XOR + 산술 연산)으로 변환한 뒤, 바이너리 내부에 하드코딩된 값과 일치하는지 비교하는 문제이다. 앞서 다룬 문제들과 달리 단순 `strcmp`가 아니라 **바이트 단위 인코딩 로직**이 걸려 있어, 정답을 얻으려면 인코딩 수식을 파악하고 이를 **역연산**해야 한다는 점이 핵심이다.

## 서비스 분석
### `main`
![main](/assets/img/posts/rev3/main.png)

`main`은 입력을 받은 뒤 `sub_7FF7B9101000` 함수를 호출하고, 그 반환값을 `test`로 검사한다. 반환값이 0이면 `"Wrong"`, 0이 아니면(1이면) `"Correct"`를 출력하는 구조다. 정답 여부를 판단하는 핵심 로직은 이 `sub_7FF7B9101000` 함수 안에 있으므로, 이 함수를 분석해야 한다.

### 검증 함수 — `sub_7FF7B9101000`
![key](/assets/img/posts/rev3/condition.png)

디컴파일 결과는 다음과 같다.

```c
__int64 __fastcall sub_140001000(__int64 a1)
{
  int i; // [rsp+0h] [rbp-18h]

  for ( i = 0; (unsigned __int64)i < 0x18; ++i )
  {
    if ( byte_140003000[i] != (i ^ *(unsigned __int8 *)(a1 + i)) + 2 * i )
      return 0;
  }
  return 1;
}
```
{: file="sub_7FF7B9101000_pseudocode.c"}

`a1`은 사용자 입력값의 포인터로 추정된다. 이 함수는 입력값을 한 바이트씩 순회하며 `byte_140003000`에 저장된 값과 아래 수식으로 변환한 값을 비교한다.

```c
byte_140003000[i] != (i ^ a1[i]) + 2 * i
```
{: file="calc.c"}

총 `0x18`(24)바이트를 모두 비교해 하나라도 다르면 즉시 `0`을 반환하고, 24바이트가 전부 일치해야 `1`을 반환해 `"Correct"`가 출력되는 구조다.

### 비교 대상 데이터 — `byte_140003000`
![val](/assets/img/posts/rev3/val.png)

`byte_140003000`에는 다음과 같이 24바이트의 데이터가 하드코딩되어 있다.

```asm
.data:00007FF7B9103000 byte_7FF7B9103000 db 49h, 60h, 67h, 74h, 63h, 67h, 42h, 66h, 80h, 78h, 2 dup(69h)
.data:00007FF7B9103000                                         ; DATA XREF: sub_7FF7B9101000+28↑o
.data:00007FF7B910300C                 db 7Bh, 99h, 6Dh, 88h, 68h, 94h, 9Fh, 8Dh, 4Dh, 0A5h, 9Dh
.data:00007FF7B9103017                 db 45h, 8 dup(0)
```
{: file="byte_7FF7B9103000.asm"}

`n dup(a)`는 "`a`를 `n`번 반복"한다는 뜻으로, `2 dup(69h)`는 `69h, 69h`와 동일하다. 뒤쪽의 `8 dup(0)`은 비교에 사용되지 않는 패딩 영역이므로 실제로 필요한 값은 앞쪽 24바이트뿐이다.

## 익스플로잇
### 역연산 도출
비교 수식은 아래와 같은 형태였다.

```
byte_140003000[i] = (i ^ input[i]) + 2*i
```

여기서 `input[i]`를 구하려면 이 식을 반대로 풀어주면 된다. 덧셈의 역연산은 뺄셈, XOR의 역연산은 **동일한 값으로 다시 XOR**하는 것이므로 다음과 같이 정리된다.

```
input[i] = (byte_140003000[i] - 2*i) ^ i
```

### 익스플로잇 스크립트
```py
byte_data = [
    0x49, 0x60, 0x67, 0x74, 0x63, 0x67, 0x42, 0x66, 0x80, 0x78, 0x69, 0x69,
    0x7B, 0x99, 0x6D, 0x88, 0x68, 0x94, 0x9F, 0x8D, 0x4D, 0xA5, 0x9D, 0x45
]

flag = ""
for i in range(24):
    decoded_byte = ((byte_data[i] - (2 * i))) ^ i
    flag += chr(decoded_byte)

print(flag)
```
{: file="exploit.py"}

각 바이트에 대해 `2*i`를 먼저 빼서 덧셈을 역연산하고, 그 결과에 다시 `i`를 XOR해서 원본 입력 바이트를 복원한다. 이 과정을 24바이트 전체에 대해 반복하면 원래 입력했어야 할 문자열, 즉 플래그가 그대로 나온다.

## 정리
* 단순 문자열 비교(`strcmp`)가 아니라 **바이트 단위 산술+XOR 인코딩**이 걸려있는 경우, 브루트포스보다는 **수식을 정확히 파악해 역연산 공식을 도출**하는 편이 훨씬 빠르고 확실하다.
* XOR은 자기 자신과 다시 XOR하면 원래 값으로 돌아온다는 성질(`(a ^ b) ^ b = a`)을 이용하면 대부분의 XOR 기반 인코딩은 역연산이 가능하다.
* 덧셈/뺄셈, XOR처럼 여러 연산이 섞여 있을 때는 **연산이 적용된 순서의 역순으로 하나씩 풀어내는 것**이 핵심이다.
