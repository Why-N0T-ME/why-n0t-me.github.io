## FSB란 무엇인가

`FSB(Format String Bug)`는 `printf()` 계열 함수의 **포맷 문자열을 사용자 입력값으로
직접 넘길 때** 발생하는 취약점이다.

```c
char buf[64];
read(0, buf, 256); //bof

// 안전한 코드
printf("%s", buf);

// 취약한 코드
printf(buf);  // buf에 "%x %x %x"가 들어오면?
```

`printf(buf)`처럼 포맷 문자열 자리에 사용자 입력이 그대로 들어오면,
공격자는 `%x`, `%s`, `%n` 같은 포맷 지정자를 입력해 메모리를 **읽거나 쓸 수** 있다.

---

## 핵심 개념: 포맷 지정자

`printf()`는 포맷 지정자의 개수만큼 추가 인자가 스택(또는 레지스터)에 있다고 가정하고
그 값을 가져온다. 공격에 주로 사용되는 지정자는 다음과 같다.

| 지정자 | 동작 | 공격 활용 |
| --- | --- | --- |
| `%x` | 스택/레지스터 값을 16진수로 출력 | 메모리 **읽기** (leak) |
| `%s` | 해당 주소가 가리키는 문자열 출력 | 특정 주소의 값 **읽기** |
| `%n` | 지금까지 출력한 문자 수를 해당 주소에 **저장** | 메모리 **쓰기** |
| `%p` | 포인터 값 출력 | 메모리 **읽기** (leak) |
| `%c` | 문자 1개 출력 (길이 조절 가능) | `%n`과 조합해 원하는 값 **쓰기** |

> **`%n`**: 출력된 문자 수를 메모리에 쓰는 지정자로,
> 공격자는 출력 길이를 조절해 원하는 값을 원하는 주소에 덮어쓸 수 있다.

---

## 동작 원리

### 32비트 환경

32비트에서는 `printf()`의 추가 인자를 **스택**에서 순서대로 가져온다.
```c
printf("AAAA %x %x %x") 호출 시 스택
┌──────────────────┐
│  "AAAA %x %x %x"│  ← 포맷 문자열 주소 (첫 번째 인자)
├──────────────────┤
│  [스택값 1]      │  ← 첫 번째 %x가 읽는 값
├──────────────────┤
│  [스택값 2]      │  ← 두 번째 %x가 읽는 값
├──────────────────┤
│  [스택값 3]      │  ← 세 번째 %x가 읽는 값
└──────────────────┘
```

`%x`를 여러 개 넣으면 스택을 위로 타고 올라가며 메모리 값이 줄줄이 출력된다.
이를 이용해 카나리 값, 반환 주소, libc 주소 등을 **leak**할 수 있다.

### 64비트 환경

64비트에서는 처음 5개의 추가 인자를 **레지스터**(`RSI`, `RDX`, `RCX`, `R8`, `R9`)에서
가져오고, 6번째부터 스택에서 가져온다.
```c
printf("AAAA %p %p %p %p %p %p %p") 호출 시:
%p 1번째 → RSI
%p 2번째 → RDX
%p 3번째 → RCX
%p 4번째 → R8
%p 5번째 → R9
%p 6번째 → 스택
%p 7번째 → 스택 ...
```

32비트보다 leak 시작 위치가 다르므로, 몇 번째 `%p`부터 스택이 나오는지
먼저 파악하는 과정이 필요하다.

---

## 두 가지 공격 방향

### 1. 메모리 읽기 (Leak)

`%x`, `%p`를 반복 입력해 스택을 덤프하면 다음과 같은 값들을 얻을 수 있다.

- **카나리 값** → 스택 카나리 우회
- **libc 주소** → ASLR 우회 (libc base 계산)
- **바이너리 주소** → PIE 우회

`%n$p` 문법으로 n번째 인자를 직접 지정해 원하는 위치의 값만 골라 읽을 수도 있다.
> printf("%3$p")  →  세 번째 인자(레지스터 or 스택)의 값만 출력

![ex](/assets/img/posts/fsb/simpleEX.png)

### 2. 메모리 쓰기 (Overwrite)

`%n`을 이용하면 **임의 주소에 원하는 값을 쓸 수 있다**.
공격자가 주로 덮어쓰는 대상은 다음과 같다.

| 덮어쓸 대상 | 효과 |
| --- | --- |
| **반환 주소** | 실행 흐름을 가로채 쉘 획득 |
| **GOT(Global Offset Table)** | 함수 호출 시 공격자가 원하는 함수로 리다이렉트 |
| **훅 함수** (`__malloc_hook` 등) | `malloc()` 호출 시 자동으로 공격자 코드 실행 |

`%n`은 출력 문자 수를 저장하므로, `%100c`처럼 출력 길이를 조절해
저장되는 값을 원하는 숫자로 맞춘다. 큰 값을 한 번에 쓰기 어려울 때는
`%hn`(2바이트), `%hhn`(1바이트) 단위로 나눠 쓰는 방법을 사용한다.

---

## ROP/RTL과의 관계

FSB는 단독으로 사용해도 강력한 공격이지만 ROP/RTL과 결합하여 보호기법을 우회하는등 더 강력한 공격이 가능하다
```
[FSB]
메모리 읽기/쓰기 → 반환 주소 직접 덮어쓰기 → 쉘 획득

[FSB + ROP]
FSB로 libc 주소 leak → ASLR 우회
→ leak한 libc base로 가젯/system() 주소 계산
→ ROP Chain으로 쉘 획득
```
> 특히 **ASLR + PIE가 동시에 걸린 환경**에서 libc 주소와 바이너리 주소를
>동시에 leak해야 할 때 FSB가 매우 유용하다.

## 요약

**FSB** - 단 한 줄의 `printf(buf)`로 메모리 읽기와 쓰기가 모두 가능한 강력한 취약점
핵심을 정리하면 다음과 같다.
- `printf(buf)`처럼 포맷 문자열을 사용자 입력으로 받으면 취약점 발생
- `%x`, `%p`로 스택/레지스터를 읽어 카나리, libc 주소 등을 **leak**
- `%n`으로 임의 주소에 값을 **write**, GOT 덮어쓰기나 반환 주소 변조에 활용
- ROP/RTL과 조합하면 ASLR, PIE가 걸린 환경도 우회 가능
