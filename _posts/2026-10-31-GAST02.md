## Intro
GAST 코드를 읽다 보면 `async`, `await`, `Promise` 같은 표기가 거의 모든 파일에 나온다. 이 글은 전체 구조 글에 이어서 이 동기/비동기 처리를 정리한 글이다.
동기와 비동기가 무엇인지, 왜 쓰는지, 어떻게 쓰는지를 먼저 정리하고, 마지막으로 GAST에서 어떤 부분을 비동기로 처리했는지 코드로 확인한다.

### 목차
- 동기와 비동기
- 왜 비동기를 쓰는가
- 어떻게 쓰는가
- GAST에서는 무엇이 비동기인가

## 동기와 비동기
- **동기(sync)**: 위에서 아래로 한 줄씩 실행한다. 앞줄이 끝나야 다음 줄로 넘어간다.
- **비동기(async)**: 결과가 나중에 도착하는 작업이다. 맡겨 두고 기다리는 동안 다른 일을 처리한다. 네트워크 요청, 파일 읽기, 타이머가 대표적이다.

```ts
console.log('A');
setTimeout(() => console.log('C'), 0);
console.log('B');
// 출력: A, B, C
```

`setTimeout`의 대기 시간이 0이어도 `C`는 마지막에 나온다. 비동기 작업의 결과는 지금 실행 중인 코드가 모두 끝난 뒤에 처리되기 때문이다.

| 용어 | 한 줄 설명 |
| --- | --- |
| `Promise` | "나중에 값이 도착한다(또는 실패한다)"는 약속 객체 |
| `async` 함수 | 항상 `Promise`를 돌려주는 함수 |
| `await` | 그 함수 안에서 결과가 올 때까지 다음 줄을 멈춘다. Node 전체가 멈추는 것은 아니다 |
| 콜백 | 나중에 호출해 달라고 넘기는 함수 (`setTimeout`의 첫 인자, GAST의 `onEvent`) |
| 이벤트 루프 | 기다리는 작업을 맡아 두었다가 결과가 오면 이어서 실행해 주는 Node의 기본 장치 |

## 왜 비동기를 쓰는가
Node.js는 JavaScript 코드를 한 번에 한 줄씩만 실행한다. 네트워크 응답처럼 오래 걸리는 일을 동기로 기다리면 그동안 프로그램 전체가 멈춘다. 비동기로 쓰면 기다리는 동안 다른 일을 처리할 수 있다.

GAST도 같은 이유로 필요하다. 검사가 돌아가는 동안에도 대시보드 서버는 브라우저의 상태 조회와 취소 요청에 응답해야 한다.

> `await`를 쓴다고 일이 동시에 실행되는 것은 아니다. 아래처럼 `await`를 하나씩 이으면 순차이고, `Promise.all`로 묶어야 동시에 진행된다. 또 오래 걸리는 동기 계산은 그동안 모든 것을 막는다.
{: .prompt-info }

```ts
await fakeFetch('/a', 30);
await fakeFetch('/b', 30);                                 // 순차: 약 60ms
await Promise.all([fakeFetch('/a', 30), fakeFetch('/b', 30)]); // 동시: 약 30ms
```

30ms 걸리는 가짜 요청 두 개를 타이머로 만들어 재 보면 순차는 약 60ms, 동시는 약 30ms가 나온다(실행할 때마다 조금씩 다르다). GAST는 속도보다 요청 순서와 안전이 중요해서 일부러 순차를 쓴다. 이유는 마지막 섹션에서 다룬다.

## 어떻게 쓰는가
### async / await
```ts
import { setTimeout } from 'node:timers/promises';

async function fakeRequest(fail: boolean): Promise<{ status: number }> {
  await setTimeout(10);
  if (fail) throw new Error('연습용 실패');
  return { status: 200 };
}
```

- 함수 앞에 `async`를 붙이면 반환값이 `Promise`로 감싸진다. 타입도 `Promise<{ status: number }>`처럼 쓴다.
- `await`는 `async` 함수 안에서만 쓸 수 있다. 그래서 `await`를 쓰는 함수는 `async`가 되고, 그 함수를 부르는 쪽도 결과가 필요하면 `await`를 써야 해서 `async`가 위로 번진다.
- 프로젝트가 ES 모듈이라서 파일 맨 위(최상위)에서도 `await`를 바로 쓸 수 있다.

### try / catch / finally
```ts
async function run(fail: boolean): Promise<void> {
  console.log('시작');
  try {
    const response = await fakeRequest(fail);
    console.log('응답', response.status);
  } catch (error) {
    console.log('실패:', (error as Error).message);
  } finally {
    console.log('정리');
  }
  console.log('종료');
}

await run(false); // 시작 → 응답 200 → 정리 → 종료
await run(true);  // 시작 → 실패: 연습용 실패 → 정리 → 종료
```

`await`한 `Promise`가 실패하면 일반 동기 코드의 예외처럼 `catch`로 들어온다. 성공하든 실패하든 `finally`와 그 뒤의 `종료`는 실행된다. 그래서 브라우저나 파일 핸들처럼 반드시 닫아야 하는 자원은 `finally`에서 정리한다.

### 삼항 연산자
GAST 코드에서 자주 보이는 `조건 ? 참일 때 값 : 거짓일 때 값` 형태이다. `if`와 달리 값을 만들어 내는 식이라서 함수 인자나 객체 속성 안에 바로 쓸 수 있다.

```ts
message: cancelled ? '사용자가 검사를 취소했습니다.' : (error as Error).message,
```
{: file="src/scanner.ts" }

여러 개를 이으면 위에서부터 `if / else if / else`로 읽으면 된다.

```ts
emit(cancelled ? '검사 취소' : discovery.errors.length ? '오류를 포함하여 종료' : '검사 종료');
```
{: file="src/scanner.ts" }

```ts
// 위 한 줄과 같은 동작
let message;
if (cancelled) message = '검사 취소';
else if (discovery.errors.length) message = '오류를 포함하여 종료';
else message = '검사 종료';
emit(message);
```

> 같이 자주 보이는 `?.`와 `??`는 값이 없을 때를 처리한다. `options.signal?.aborted ?? false`는 `signal`이 없으면 에러 대신 `undefined`가 되고, `??`가 그것을 `false`로 바꾼다.
{: .prompt-tip }

## GAST에서는 무엇이 비동기인가
**기준은 I/O가 있느냐**이다. 네트워크, 파일, 브라우저처럼 기다려야 하는 일은 `async`로, 이미 받은 데이터를 계산만 하는 일은 일반(동기) 함수로 둔다.

| 구분 | 함수 | 이유 |
| --- | --- | --- |
| 동기 | `originOf`, `canonical`, `scoped`, `pointKey` (`scope.ts`) | URL 처리, 네트워크 없음 |
| 동기 | `parsePage`, `reflectionContext`, `hasExecutableMarker` (`html.ts`) | 받은 HTML을 파싱만 함 |
| 동기 | `similarity`, `compare`, `passive` (`rules.ts`), `validateOptions` (`scanner.ts`) | 이미 받은 응답이나 값을 계산 |
| 비동기 | `HttpClient.request`, `HttpClient.login` (`http.ts`) | 네트워크 |
| 비동기 | `openBrowser`, `browserCrawl`, `verifyXss` (`browser.ts`) | Chromium 제어 |
| 비동기 | `writeReport` (`report.ts`), studio와 lab의 요청 핸들러 | 파일, HTTP 서버 |
| 비동기 | `crawl`, `send`, `testInput`, `scan` | 위의 요청 함수를 부르므로 함께 `async` |

마지막 줄이 앞에서 말한 "`async`가 위로 번진다"의 실제 모습이다. `scan` → `crawl` / `testInput` → `send` → `request` → `fetch`가 전부 `async`이다.

### 1. 요청 하나 (`http.ts`)
모든 HTTP 요청이 지나가는 `HttpClient.request`는 비동기 처리가 가장 많이 모인 곳이다.

```ts
await new Promise((resolve) => setTimeout(resolve, this.delay));
this.options.signal?.throwIfAborted();
this.count++;
// ...
const timeout = AbortSignal.timeout(this.timeout),
  signal = this.options.signal ? AbortSignal.any([timeout, this.options.signal]) : timeout;
const response = await fetch(url, { method, body, headers, redirect: 'manual', signal });
```
{: file="src/http.ts" }

- `await new Promise((resolve) => setTimeout(resolve, this.delay))`는 타이머를 `Promise`로 감싸서 요청 사이에 `delay`(기본 15ms)만큼 쉬는 부분이다.
- `throwIfAborted()`는 이미 취소 신호가 와 있으면 그 자리에서 예외를 던진다. 요청 전, 대기 후처럼 길게 기다리기 전후에 둔 취소 체크포인트이다.
- `AbortSignal.timeout`(시간 제한)과 사용자 취소 신호를 `AbortSignal.any`로 합쳐서 `fetch`에 넘긴다. 둘 중 먼저 오는 쪽에서 요청이 중단된다.
- 응답 본문은 한 번에 읽지 않고 `await reader.read()`로 조각씩 읽으며 1 MiB를 넘으면 중단하고, `finally`에서 스트림을 닫는다.

### 2. 일부러 순차로 보낸다
```ts
const baselines = [await send(client, point), await send(client, point)];
```
{: file="src/scanner.ts" }

정상 응답 두 개를 차례로 받는 줄이다. 배열 안에서도 `await`는 왼쪽부터 평가되므로 첫 요청이 실패하면 두 번째는 시작도 하지 않는다. `src/` 전체에 `Promise.all`은 한 번도 없고, `test/browser.test.ts`에서 테스트 서버 두 개를 동시에 닫을 때만 쓰인다. 순차로 보내는 이유는 세 가지이다.

- **증거의 의미**: 기준 → 검사 → 대조 → 재검사 순서가 깨지면 응답을 비교하는 의미가 없어진다.
- **요청 예산**: 요청 시도 수(`count`)를 `fetch` 직전에 올리므로, 동시에 보내면 한도 관리가 복잡해진다.
- **대상 서버 보호**: `delay` 간격을 지켜 서버에 부담을 주지 않는다.

### 3. 기다리지 않고 시작한다 (`studio.ts`)
대시보드에서 검사를 시작하면 서버는 검사가 끝날 때까지 응답을 붙잡지 않는다.

```ts
void scan(job.target, options)
  .then(async (result) => {
    job.result = result;
    await writeReport(result, `reports/runs/${id}`);
    job.state = 'done';
  })
  .catch((error) => {
    job.error = (error as Error).message;
    job.state = 'failed';
  });
json(202, { id });
```
{: file="src/studio.ts" }

- 맨 앞의 `void scan(...)`에는 `await`가 없다. 검사를 시작만 하고 바로 다음 줄로 넘어가서 `202`(접수됨)와 `id`를 응답한다. 화면은 650ms마다 `GET /api/scans/:id`로 진행 상황을 가져간다(폴링).
- 기다리지 않으니 실패를 받아 줄 곳이 없어서 `.catch`가 반드시 필요하다. 처리하지 않은 `Promise` 실패는 Node 프로세스를 종료시킨다.
- `state`는 보고서 파일 저장까지 끝난 뒤에 `done`이 된다. 저장이 실패하면 `failed`이다.

### 4. 취소와 시간 제한
검사 취소는 `AbortController` 하나로 전달된다. 대시보드는 검사(Job)마다 컨트롤러를 만들고, CLI는 `Ctrl+C`를 `abort()`에 연결한다. 이 신호가 `options.signal`로 `HttpClient`, 크롤러, 스캐너, 브라우저 루프까지 내려간다.

> 타임아웃은 `TimeoutError`, 사용자 취소는 `AbortError`로 오류 이름이 다르다. 그래서 GAST는 오류 이름이 아니라 사용자 신호의 `signal.aborted`로 취소 여부를 판단한다. 취소가 오류와 어떻게 다르게 처리되는지는 전체 구조 글의 Pipeline 섹션에 있다.
{: .prompt-info }

### 정리

| 비동기로 처리한 것 | 위치 | 방식 |
| --- | --- | --- |
| HTTP 요청과 응답 읽기 | `http.ts` | `async`/`await`, 한 요청씩 순차 |
| 요청 간 대기 | `http.ts` | 타이머를 `Promise`로 감쌈 |
| 시간 제한과 취소 | `http.ts`, `scanner.ts`, `crawler.ts` | `AbortSignal`, `throwIfAborted()` |
| Chromium 탐색과 XSS 실행 확인 | `browser.ts` | `async` 함수, 취소 체크 |
| 검사 시작과 상태 조회 | `studio.ts`, `web/app.js` | `void scan()` + `202` + 650ms 폴링 |
| 보고서 저장 | `report.ts` | `async` 파일 쓰기 |
| 자원 정리 | `http.ts`, `browser.ts` | `finally` |

GAST의 비동기는 "빠르게 동시에 보내기"가 목적이 아니다. 기다려야 하는 I/O는 `async`로 두되, 요청 순서와 예산, 취소를 정확히 지키기 위해 순차로 보낸다.
