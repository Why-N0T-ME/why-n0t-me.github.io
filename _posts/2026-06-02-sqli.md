## Concept
**SQLi**는 공격자가 웹페이지의 로그인, 검색창, URL파라미터, 게시글 조회등 DB쿼리가 실행되는 **입력값에 조작된 SQL쿼리문을 삽입**하여 조작된 쿼리문이 실행되게 하는 공격으로  **인증우회, 데이터 탈취, 데이터 변조및 삭제, 서버 명령 실행**같은 피해가 발생할 수 있다.
웹 서비스가 사용자의 입력값을 *검증없이 SQL쿼리에 직접 연결할때 발생*한다.

EX>> 로그인 요청을 할때 사용자가 입력한 id와 pw를 query=“SELECT * FROM users WHERE name=’$name’ AND pw=’$pw’”; 같이 DB로 쿼리를 보내 처리할때

Id=Jake / pw = pass 같이 입력하면 query값에 name=’Jake’ AND pw=’pass’ 같이 담기는데 Id=admin’ -- / pw = asdad(아무 값) 같이 입력하면 name ‘admin’-- ‘AND pw=’asdad’ 같이 쿼리가 날아가는데 -- 뒷부분은 주석처리되어 pw가 맞는지 검사하지 않아 admin계정으로 로그인에 성공

## 서비스 분석
### `/login`
```python
@app.route('/login', methods=['GET', 'POST'])
def login():
    if request.method == 'GET':
        return render_template('login.html')
    else:
        userid = request.form.get('userid')
        userpassword = request.form.get('userpassword')
        res = query_db(f'select * from users where userid="{userid}" and userpassword="{userpassword}"')
        if res:
            userid = res[0]
            if userid == 'admin':
                return f'hello {userid} flag is {FLAG}'
            return f'<script>alert("hello {userid}");history.go(-1);</script>'
        return '<script>alert("wrong");history.go(-1);</script>'
```
{: file="login.py"}

Simple-sqli 문제에는 `/login` 엔드포인트만 존재하며 DB와 연동해서 ID, PW값을 입력받아 그대로 SQL쿼리문에 집어넣어 처리한다.
이때, 사용자의 입력값(userid, userpassword)을 SQL쿼리문에 넣을때 특수문자 필터링을 거치지 않고 입력한 값을 그대로 사용하므로 `" , OR AND --` 같이 SQL문법을 사용해서 SQLi을 수행할수 있다.

### 익스플로잇
```python
ID: admin " --
PW: Any
```

로그인에 필요한 파라미터를 필터링없이 원본 그대로 쿼리문에 집어넣어 인증을 처리하는데 이때 SQL구문을 삽입하면 인증을 처리하는 식이 제대로 작동하지 않아 에러를 내거나 항상 참인 식이 되어 인증우회가 가능하다.
`exploit.py`처럼 입력하면 *--*뒤에 나오는  *and userpassword="{userpassword}"* 가 주석처리되어 아이디만 맞으면 로그인에 성공한다.
