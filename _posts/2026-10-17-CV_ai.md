### Intro

![prob](/assets/img/posts/Crypto/26대회/고전암호분석/5prob.png)
5번 문제는 ciphertexts1.txt와 ciphertexts2.txt를 학습 데이터로 AI 분류기 모델을 생성하고, 주어진 4개의 암호문이 시저 암호와 비제네르 암호 중 어떤 유형으로 암호화되었는지 구분하는 문제다. 답안에는 다음이 필요하다.

- 모델 및 학습 feature를 자세하게 기술
- AI 모델의 논리적인 설계 근거
- 분류 모델 코드와 실행문

판별할 암호문 4개는 다음과 같다.

```text
암호문 1  NKRRUZNOYOYGIRGYYOIGRIOVNKXGTGREYOYVXUHRKSLUXZNKIXEVZGTGREYOYIUSVKZOZOUTIUTMXGZARG
          ZOUTYUTMKZZOTMZNKIUXXKIZGTYCKX
암호문 2  ROVVYDRSCSCKMVKCCSMKVMSZROBKXKVICSCZBYLVOWPYBDROMBIZDKXKVICSCMYWZODSDSYXMYXQBKD
          EVKDSYXCYXQODDSXQDROMYBBOMDKXCGOB
암호문 3  DRKXUIYEPYBIYEBZKBDSMSZKDSYXGOGSCRIYEKVVDROLOCDSXIYEBPEDEBOOXNOKFYBC
암호문 4  ZNGTQEUALUXEUAXVGXZOIOVGZOUTCKCOYNEUAGRRZNKHKYZOTEUAXLAZAXKKTJKGBUXY
```

앞선 글에서는 고전 암호를 수학적, 통계적인 방법으로 직접 암호문을 해독해봤다면, 이번 문제는 "비제네르와 시저 암호의 특징을 AI에게 학습시키는 것"이 목적이다. 따라서 무엇을 기준으로 판단할지를 먼저 생각해야 한다.

앞의 문제를 풀면서 내가 비제네르와 시저 암호를 구분한 기준은 `일치지수(IC)` 뿐이다. `1-2`에서 일치지수를 기준으로 어떤 암호화가 사용되었는지 구분했었는데, 좀 더 두 암호화의 특징을 반영하여 분류하도록 구현하는 게 정확도가 높을 것이다.

### 분류 기준

시저 사이퍼와 비제네르 사이퍼의 차이점을 생각해보자.

|암호화 방식|차이점|
|---|---|
| Caesar Cipher | 빈도가 쏠림 / IC가 비교적 높음(약 0.067) |
| Vigenere Cipher | 빈도가 평평함(분산됨) / IC가 비교적 낮음(약 0.038~0.044) |

단순히 일치지수(IC)만 보지 말고 단어의 빈도 쏠림 정도도 반영해서 암호화의 유형을 판단하도록 하겠다.

#### 왜 IC로 구분이 되는가

일치지수는 암호문에서 임의로 두 글자를 뽑았을 때 같은 글자일 확률이다.

$$IC = \frac{\sum_{i=0}^{25} n_i (n_i - 1)}{N(N-1)}$$

- 시저는 모든 글자를 같은 만큼 미는 단일 치환이다. 글자 빈도의 "모양"은 그대로이고 위치만 이동하므로, IC는 평문(영어 약 0.067)과 같다. 그래서 shift가 몇이든 같은 기준으로 판별할 수 있다.
- 비제네르는 키 길이 $L$개의 서로 다른 시저가 섞여서 빈도가 평평해진다. 완전히 균등하면 $1/26 \approx 0.0385$이고, 키가 길수록 이 값에 가까워진다.

프리드먼 공식으로 IC에서 키 길이를 역산할 수도 있다.

$$L \approx \frac{0.0265N}{(N-1)\,IC - 0.0385N + 0.0667}$$

학습 파일의 IC를 측정하면 ciphertexts1은 0.0676(시저), ciphertexts2는 0.0440(비제네르)이다. 위 표의 기준과 맞고, ciphertexts2의 키 길이는 프리드먼 공식으로 약 5로 추정된다.

#### 사용한 특징 (feature)

IC 하나만 쓰면 글자 수가 적을 때 값이 크게 흔들리고, 키 길이가 짧은 비제네르(키 길이 2는 IC 약 0.053)는 시저와 가까워진다. 그래서 빈도 쏠림을 보는 특징을 같이 썼다. 텍스트(또는 청크) 하나에서 다음 6개를 뽑는다. $f_i$는 알파벳 $i$의 상대 빈도다.

| 특징 | 식 | 보는 것 |
|---|---|---|
| IC | $\sum n_i(n_i-1) / N(N-1)$ | 분포의 쏠림 정도 (핵심) |
| 최대 빈도 | $\max f_i$ | 시저에서 특정 글자(E가 이동한 글자)가 튀는 정도 |
| 빈도 표준편차 | $\mathrm{std}(f_i)$ | 분포가 얼마나 들쭉날쭉한가 |
| 엔트로피 | $-\sum f_i \log_2 f_i$ | 분포의 무질서도 (평탄할수록 높음) |
| 상위 3개 합 | 가장 큰 $f_i$ 3개의 합 | 상위 글자에 빈도가 몰린 정도 |
| 카이제곱(균등분포 대비) | $\sum (f_i - 1/26)^2 / (1/26)$ | 균등분포에서 얼마나 벗어났는가 |

학습 데이터(60자 청크)에서 측정한 평균은 다음과 같다. 세 특징 모두 시저가 높게 나온다.

| | IC | 최대 빈도 | 빈도 표준편차 |
|---|---|---|---|
| 시저 | 0.0647 | 0.141 | 0.0399 |
| 비제네르 | 0.0431 | 0.106 | 0.0278 |

다만 IC, 빈도 표준편차, 카이제곱은 모두 $\sum f_i^2$에서 계산되는 값이라 거의 같은 정보다(카이제곱 $= 26\sum f_i^2 - 1$). 실제로 새 정보를 더해 주는 것은 최대 빈도, 상위 3개 합, 엔트로피다.

### 모델 설계 근거

**문제 정의.** 알파벳 글자열 하나를 입력받아 시저(0) 또는 비제네르(1)로 분류하는 이진 분류다. 입력 단위는 고정 길이 청크이고, 암호문 전체가 아니라 청크에서 특징을 뽑는다.

**평문이 같다는 점.** 문제에서 두 암호문은 동일한 평문을 각각 다른 방식으로 암호화한 것이다. 그래서 학습 데이터에서 두 클래스의 차이는 평문 내용이 아니라 암호 방식뿐이다. 모델이 "어떤 문장이냐"가 아니라 "빈도 분포가 어떻게 생겼냐"만 학습하게 되므로, 빈도 기반 특징을 쓰는 설계와 잘 맞는다.

**모델을 3개 둔 이유.** 모델 하나에 의존하지 않고 성격이 다른 3개를 만들어 비제네르일 확률의 평균으로 최종 판정한다(0.5 이상이면 비제네르).

1. **규칙 기반**: IC가 0.053 이상이면 시저 1표, 빈도 표준편차가 학습 데이터의 두 클래스 평균의 중간값 이상이면 시저 1표를 준다. 2표면 시저, 0표면 비제네르이고 표가 갈리면 IC를 따른다. 이론에서 나온 기준이라 근거를 설명하기 쉽고 학습이 필요 없다.
2. **로지스틱 회귀**: 특징을 표준화하고 선형 경계를 학습한다. 데이터가 적어도 안정적이고 확률을 출력한다.
3. **랜덤 포레스트**: 특징 사이의 비선형 관계를 잡고, 앙상블이라 과적합이 덜하다. `random_state=0`으로 고정해서 결과가 재현된다.

학습 데이터가 파일 2개(약 19,900자씩)뿐이라 딥러닝 같은 복잡한 모델은 오히려 부적절하다고 판단했다.

**청크 길이.** 파일 하나를 고정 길이 청크로 잘라 샘플 수를 늘렸다. 청크가 길수록 특징이 안정적이라 정확도가 높지만, 판별할 암호문은 68~112자로 짧다. 청크 길이별 검증 정확도를 측정했다.

| 청크 길이 | 학습/검증 청크 수 | 규칙 | 로지스틱 | 랜덤 포레스트 |
|---|---|---|---|---|
| 300자 | 92 / 40 | 1.000 | 1.000 | 1.000 |
| 150자 | 184 / 80 | 1.000 | 1.000 | 1.000 |
| 100자 | 276 / 120 | 0.992 | 1.000 | 1.000 |
| 60자 | 462 / 200 | 0.925 | 0.945 | 0.950 |

청크가 길수록 정확하지만 샘플 수가 줄어든다. 판별할 암호문 중 가장 짧은 것이 68자라서, 그보다 짧은 60자 청크로 학습해서 짧은 입력에서의 성능을 직접 확인하는 쪽을 택했다.

**검증 방식.** 파일 앞 70%는 학습, 뒤 30%는 검증으로 나눠서 같은 구간이 학습과 검증에 함께 들어가지 않게 했다.

### 구현 코드

```python
"""ciphertexts1.txt(시저), ciphertexts2.txt(비제네르)로 학습하고
주어진 암호문 4개가 시저/비제네르 중 무엇인지 판별해 출력한다.

실행:  python classify_four.py
       python classify_four.py --c1 ciphertexts1.txt --c2 ciphertexts2.txt --chunk 60
필요:  numpy, scikit-learn
"""
import argparse
import re
from collections import Counter

import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

# 판별할 암호문 4개
TARGETS = {
    "암호문 1": "NKRRUZNOYOYGIRGYYOIGRIOVNKXGTGREYOYVXUHRKSLUXZNKIXEVZGTGREYOYIUSVKZOZOUTIUTMXGZARGZOUTYUTMKZZOTMZNKIUXXKIZGTYCKX",
    "암호문 2": "ROVVYDRSCSCKMVKCCSMKVMSZROBKXKVICSCZBYLVOWPYBDROMBIZDKXKVICSCMYWZODSDSYXMYXQBKDEVKDSYXCYXQODDSXQDROMYBBOMDKXCGOB",
    "암호문 3": "DRKXUIYEPYBIYEBZKBDSMSZKDSYXGOGSCRIYEKVVDROLOCDSXIYEBPEDEBOOXNOKFYBC",
    "암호문 4": "ZNGTQEUALUXEUAXVGXZOIOVGZOUTCKCOYNEUAGRRZNKHKYZOTEUAXLAZAXKKTJKGBUXY",
}
CAESAR, VIGENERE = 0, 1
NAMES = {CAESAR: "시저", VIGENERE: "비제네르"}


def clean(text):
    return re.sub(r"[^A-Za-z]", "", text).upper()


def freqs(t):
    c = Counter(t)
    return np.array([c.get(chr(65 + i), 0) / len(t) for i in range(26)])


def ioc(t):
    c = Counter(t)
    return sum(v * (v - 1) for v in c.values()) / (len(t) * (len(t) - 1))


def features(t):
    """[IoC, 최대빈도, 빈도표준편차, 엔트로피, 상위3합, 균등분포 대비 카이제곱]"""
    f = freqs(t)
    nz = f[f > 0]
    return np.array([
        ioc(t), f.max(), f.std(), float(-(nz * np.log2(nz)).sum()),
        float(np.sort(f)[-3:].sum()), float(((f - 1 / 26) ** 2 / (1 / 26)).sum()),
    ])


def chunks(path, size):
    t = clean(open(path, encoding="utf-8", errors="ignore").read())
    return [t[i:i + size] for i in range(0, len(t) - size + 1, size)]


def train_and_classify(c1, c2, chunk=60):
    """두 학습 파일로 분류기를 학습하고 TARGETS 4개를 판별한다.
    반환: {암호문 이름: {"text", "verdict"("시저"/"비제네르"), "p_vigenere", "ioc"}}"""
    a = argparse.Namespace(c1=c1, c2=c2, chunk=chunk)

    # 1) 학습 데이터: 파일 앞 70% 학습 / 뒤 30% 검증
    Xtr, ytr, Xva, yva = [], [], [], []
    for label, path in ((CAESAR, a.c1), (VIGENERE, a.c2)):
        cs = chunks(path, a.chunk)
        cut = int(len(cs) * 0.7)
        for part, X, y in ((cs[:cut], Xtr, ytr), (cs[cut:], Xva, yva)):
            X += [features(c) for c in part]
            y += [label] * len(part)
    Xtr, ytr, Xva, yva = map(np.array, (Xtr, ytr, Xva, yva))
    thr = (Xtr[ytr == CAESAR, 2].mean() + Xtr[ytr == VIGENERE, 2].mean()) / 2  # 빈도 쏠림 임계값

    lr = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(Xtr, ytr)
    rf = RandomForestClassifier(n_estimators=200, random_state=0).fit(Xtr, ytr)

    def rule(x):  # IoC(0.053 기준) + 빈도 쏠림 투표, 동률이면 IoC 우선
        v_ioc, v_flat = x[0] >= 0.053, x[2] >= thr
        return CAESAR if (v_ioc and v_flat) else VIGENERE if not (v_ioc or v_flat) else (CAESAR if v_ioc else VIGENERE)

    print(f"[학습] 청크 {a.chunk}자 | 학습 {len(ytr)}개 / 검증 {len(yva)}개")
    for k in (CAESAR, VIGENERE):
        m = Xtr[ytr == k].mean(axis=0)
        print(f"  {NAMES[k]} 평균: IoC={m[0]:.4f} 최대빈도={m[1]:.3f} 빈도표준편차={m[2]:.4f}")
    print(f"[검증 정확도] 규칙={np.mean([rule(x) == y for x, y in zip(Xva, yva)]):.3f} "
          f"로지스틱={lr.score(Xva, yva):.3f} 랜덤포레스트={rf.score(Xva, yva):.3f}\n")

    # 2) 암호문 4개 판별
    print("=" * 72)
    results = {}
    for name, ct in TARGETS.items():
        t = clean(ct)
        x = features(t)
        p_lr = lr.predict_proba([x])[0, VIGENERE]
        p_rf = rf.predict_proba([x])[0, VIGENERE]
        p_rule = float(rule(x))
        p = (p_lr + p_rf + p_rule) / 3  # 비제네르 종합 확률
        verdict = NAMES[VIGENERE if p >= 0.5 else CAESAR]
        print(f"{name} ({len(t)}자)  IoC={x[0]:.4f}  최대빈도={x[1]:.3f}  빈도표준편차={x[2]:.4f}")
        print(f"   비제네르 확률  로지스틱={p_lr:.2f}  랜덤포레스트={p_rf:.2f}  규칙={p_rule:.0f}  종합={p:.2f}")
        print(f"   ==> 판정: {verdict}")
        print("-" * 72)
        results[name] = {"text": t, "verdict": verdict, "p_vigenere": p, "ioc": x[0]}
    return results


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--c1", default="ciphertexts1.txt", help="시저 학습 파일")
    ap.add_argument("--c2", default="ciphertexts2.txt", help="비제네르 학습 파일")
    ap.add_argument("--chunk", type=int, default=60, help="학습 청크 길이(글자 수)")
    a = ap.parse_args()
    train_and_classify(a.c1, a.c2, a.chunk)


if __name__ == "__main__":
    main()
```

코드의 흐름은 다음과 같다.

- `clean`: 알파벳만 남기고 대문자로 통일
- `features`: 텍스트에서 특징 6개를 뽑음 (IC, 최대 빈도, 빈도 표준편차, 엔트로피, 상위 3개 합, 카이제곱)
- `chunks`: 파일을 고정 길이 조각으로 분할
- `rule`: IC와 빈도 쏠림으로 판정하는 규칙 기반 분류
- `train_and_classify`: 학습 → 검증 정확도 출력 → 암호문 4개 판별 (`verify_four.py`에서도 불러 씀)

### 복호화로 검증

분류기의 판정은 통계적 추정이라, AI가 판별한 방식 그대로 암호문 4개를 복호화해서 의미있는 영문이 나오는지 확인한다. 복호화 함수는 앞선 풀이(3, 4번)에서 작성한 코드를 그대로 가져와 사용했다.

- **시저**: k=1~25 전수조사 → 카이제곱이 가장 작은 키 → $(c - k) \bmod 26$ (`KAI.py`, `decrypt.py`)
- **비제네르**: 일치 수로 키 길이 → 묶음별 최빈 글자를 E로 가정해 키 → $(c - key) \bmod 26$ (`vigenere.py`)

```python
"""AI 분류기가 판별한 암호 방식대로 암호문 4개를 복호화해서 의미있는 글이 나오는지 확인한다.

흐름
  1) classify_four.py 의 분류기로 암호문 4개를 판별 (시저 / 비제네르)
  2) 판별된 방식으로 복호화 (복호화 코드는 풀이 글의 코드 그대로)
       - 시저    : k=1~25 전수조사 + 카이제곱 적합도 검정으로 키 결정 → (c - k) mod 26
       - 비제네르: 일치 수로 키 길이 → 묶음별 최빈 글자(E)로 키 → (c - key) mod 26
  3) 암호문마다  "AI 판별 → 해독 결과"  를 출력

실행:  python verify_four.py     (classify_four.py, ciphertexts1.txt, ciphertexts2.txt 와 같은 폴더)
"""
import contextlib
import io
import string
from collections import Counter

import classify_four as cf # AI분류기

# [표 1] 영어 알파벳 빈도표(%)
ENG = {"A": 8.17, "B": 1.5, "C": 2.78, "D": 4.25, "E": 12.7, "F": 2.23,
       "G": 2.02, "H": 6.09, "I": 6.97, "J": 0.15, "K": 0.77, "L": 4.03,
       "M": 2.41, "N": 6.75, "O": 7.51, "P": 1.93, "Q": 0.1, "R": 5.99,
       "S": 6.33, "T": 9.06, "U": 2.76, "V": 0.98, "W": 2.36, "X": 0.15,
       "Y": 1.97, "Z": 0.07}


# ---------------------------------------------------------------------------
# 시저
# ---------------------------------------------------------------------------
def decrypt_caesar(ct, k):
    """왼쪽으로 k칸 이동"""
    return "".join(chr((ord(c) - ord("A") - k) % 26 + ord("A")) for c in ct)


def chi_square(plain):
    """영어 빈도표 기준 카이제곱 통계량 (작을수록 영어와 비슷)"""
    n = len(plain)
    ni = Counter(plain)
    return sum((ni.get(ch, 0) - n * ENG[ch] / 100) ** 2 / (n * ENG[ch] / 100)
               for ch in string.ascii_uppercase)


def find_caesar_key(ct):
    """k = 1~25 전수조사 후 카이제곱이 가장 작은 키"""
    return min(range(1, 26), key=lambda k: chi_square(decrypt_caesar(ct, k)))


# ---------------------------------------------------------------------------
# 비제네르
# ---------------------------------------------------------------------------
def find_key_length(ct):
    """shift칸 민 암호문과의 일치 수가 가장 큰 shift (1~29)"""
    n = len(ct)
    results = []
    for shift in range(1, min(30, n)):
        shifted = " " * shift + ct[:-shift]
        results.append((shift, sum(1 for i in range(n) if ct[i] == shifted[i])))
    return max(results, key=lambda x: x[1])[0]


def find_actual_key(ct, key_len, most_frequent="E"):
    """묶음마다 가장 많이 나온 글자가 E라고 가정하고 키 계산"""
    key = ""
    for col in range(key_len):
        common = Counter(ct[col::key_len]).most_common(1)[0][0]
        key += chr(ord("A") + (ord(common) - ord(most_frequent)) % 26)
    return key


def decrypt_vigenere(ct, key):
    return "".join(chr(ord("A") + (ord(c) - ord(key[i % len(key)])) % 26)
                   for i, c in enumerate(ct))


# ---------------------------------------------------------------------------
def decrypt_by_ai_verdict(ct, method):
    """AI가 판별한 방식에 맞게 키를 추정하고 복호화"""
    if method == "시저":
        k = find_caesar_key(ct)
        return f"키 {chr(ord('A') + k)}, shift {k}", decrypt_caesar(ct, k)
    key = find_actual_key(ct, find_key_length(ct))
    return f"키 {key}", decrypt_vigenere(ct, key)


if __name__ == "__main__":
    with contextlib.redirect_stdout(io.StringIO()):  # 분류기 학습 로그는 숨김
        results = cf.train_and_classify("ciphertexts1.txt", "ciphertexts2.txt", 60)

    for name, r in results.items():
        key_info, plain = decrypt_by_ai_verdict(r["text"], r["verdict"])
        print(f"{name}: AI 판별 - {r['verdict']} ({key_info})")
        print(f"  해독 결과: {plain}\n")
```

### 한계

- 학습한 비제네르는 키가 하나(길이 5)뿐이라 다른 키 길이에서도 잘 되는지는 검증하지 못했다.
- 영어 평문을 가정한다. 다른 언어는 기준 IC가 달라진다.
- 짧은 텍스트(3, 4번)는 IC가 중간 영역에 나와 구분이 어렵다. 청크 길이별 정확도 표에서도 짧을수록 정확도가 떨어졌다.
- 키 길이 1인 비제네르는 시저와 같아서 통계만으로는 구분할 수 없다. 다만, 키 길이가 1인 비제네르를 사용하는 경우는 있을까 싶다
- 그래서 분류기의 판정은 통계적 추정이고, 복호화로 영어 문장이 나오는지 확인하는 것이 확정 절차다.

개선한다면 시저 전수 복호화 점수(영어 빈도와의 카이제곱)를 특징으로 추가하고, 키 길이를 다양하게 한 비제네르 학습 데이터를 만들어 볼 수 있다.

### 정리

- IC는 시저(약 0.067)와 비제네르(키가 길수록 약 0.038)를 가르는 핵심 특징이고, 빈도 쏠림 특징(최대 빈도, 상위 3개 합, 엔트로피)이 이를 보완한다.
- 규칙 기반, 로지스틱 회귀, 랜덤 포레스트 3개의 확률을 평균내서 판정했고, 4개 암호문은 모두 시저로 판별되었다.
- 판별 결과는 시저 복호화(키 G, K, K, G)로 의미있는 영문이 나오는 것으로 검증했다.
- 통계적 분류는 짧은 암호문에서 확신도가 낮아지므로, 복호화해서 읽어보는 확인이 같이 필요하다.
