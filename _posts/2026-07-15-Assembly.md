## Introduction

리버싱이나 익스플로잇을 진행하다 보면 결국 디스어셈블된 어셈블리어 코드를 읽고 해석하는 과정을 피할 수 없다. 하지만 어셈블리어는 **아키텍쳐마다 문법이 다르고, 같은 아키텍쳐 안에서도 어셈블러에 따라 표기 방식이 갈린다.** 대표적으로 GNU Assembler가 쓰는 **AT&T 문법**과 NASM(Netwide Assembler)이 쓰는 **Intel 문법**이 있다.

본격적으로 바이너리를 분석하기 전에, 이번 글에서는 x64 어셈블리어의 기본 구성 요소와 자주 등장하는 명령어들을 카테고리별로 정리해본다.

### Concept: 명령어와 피연산자

x64 어셈블리 언어는 **명령어(Operation Code)** 와 **피연산자(Operand)** 로 구성된다.

* **명령어**: 어떤 동작을 수행할지 지정 (예: `mov`, `add`, `jmp`)
* **피연산자**: 그 동작의 대상 — 상수, 레지스터, 또는 `TYPE PTR [메모리]` 형태의 메모리 주소

메모리에서 값을 가져올 때는 몇 바이트를 읽을지 **크기 지정자**로 명시해야 한다.

| 지정자 | 크기 |
| :--- | :--- |
| `BYTE PTR` | 1 byte |
| `WORD PTR` | 2 byte |
| `DWORD PTR` | 4 byte |
| `QWORD PTR` | 8 byte |

명령어는 역할에 따라 아래와 같이 분류할 수 있다.

* **데이터 이동(Data Transfer)** — `mov`, `lea`
* **산술 연산(Arithmetic)** — `inc`, `dec`, `add`, `sub`, `mul`, `imul`, `div`, `idiv`
* **논리 연산(Logical)** — `and`, `or`, `xor`, `not`
* **비교(Comparison)** — `cmp`, `test`
* **분기(Branch)** — `jmp`, `je`, `jg` 등
* **스택(Stack)** — `push`, `pop`
* **프로시져(Procedure)** — `call`
* **시스템콜(System call)** — `syscall`

## Mechanism: 카테고리별 주요 명령어

### 1. 데이터 이동 — `mov`, `lea`

```nasm
mov dest, src   ; dest = src  (register, memory, immediate 조합 가능)
lea dest, src   ; dest = src의 유효 주소(Effective Address)
```
{: file="data_transfer.nasm"}

`mov`와 `lea`의 차이가 핵심이다. `mov`는 **메모리에 직접 접근해서 값을 가져오는** 반면, `lea`는 메모리에 접근하지 않고 **유효 주소(포인터)를 계산해서 저장**한다. 즉 `mov`가 "메모리에서 값을 읽어와 계산한다"면, `lea`는 "메모리 주소 자체를 가지고 계산한다"고 이해하면 된다.

### 2. 산술 연산 — `add`, `sub`, `mul`/`imul`, `div`/`idiv`

```nasm
add dest, src   ; dest += src
sub dest, src   ; dest -= src
inc dest        ; dest += 1
dec dest        ; dest -= 1
```
{: file="arithmetic.nasm"}

곱셈·나눗셈은 연산 결과 크기가 피연산자 크기와 달라질 수 있어 별도의 규칙을 따른다.

```nasm
mul src               ; 피연산자 1개, 부호 없는 곱셈
                       ; AL/AX/EAX/RAX * src => AX/DX:AX/EDX:EAX/RDX:RAX

imul src               ; 피연산자 1개
imul dest, src          ; 피연산자 2개, dest *= src
imul dest, src, imm     ; 피연산자 3개, dest = src * imm
```
{: file="mul_imul.nasm"}

`imul`은 **부호 있는** 정수, `mul`은 **부호 없는** 정수를 다룬다. `mul`은 피연산자가 1개뿐이지만 `imul`은 최대 3개까지 받을 수 있다. `imul` 연산 결과가 목적지 피연산자 크기를 초과해 데이터 손실이 발생하면 Carry Flag(CF)와 Overflow Flag(OF)가 1로 설정되고, 손실 없이 저장되면 두 플래그 모두 0이 된다.

```nasm
div src    ; 부호 없는 나눗셈
idiv src   ; 부호 있는 나눗셈
```
{: file="div.nasm"}

피제수는 크기에 따라 `AX` / `DX:AX` / `EDX:EAX` / `RDX:RAX`에 저장되고, 연산 결과인 몫과 나머지는 각각 `AL:AH` / `AX:DX` / `RAX:RDX`에 저장된다.

### 3. 논리 연산 — `and`, `or`, `xor`, `not`

```nasm
and dest, src   ; 두 비트가 모두 1일 때 1 → 비트마스킹에 사용
or  dest, src   ; 둘 중 하나라도 1이면 1 → 특정 비트 설정
xor dest, src   ; 두 비트가 다를 때 1 → 비트 토글, 암호화 등에 사용
not dest        ; 비트 반전
```
{: file="logical.nasm"}

### 4. 비교 연산 — `cmp`, `test`

```nasm
cmp dest, src   ; dest - src 연산으로 플래그만 갱신 (결과는 저장하지 않음)
test dest, src  ; dest AND src 연산으로 플래그만 갱신
```
{: file="compare.nasm"}

`cmp`는 두 피연산자를 **뺀 결과**로, `test`는 **AND 연산한 결과**로 플래그 레지스터를 갱신한다는 점이 다르다. `test`는 주로 특정 비트나 레지스터가 0인지 아닌지 판별할 때 쓰인다.

`cmp rax, rbx` 실행 시 플래그가 어떻게 설정되는지 예시로 정리하면 다음과 같다.

| rax | rbx | ZF(Zero) | SF(Sign) | OF(Overflow) |
| :--- | :--- | :---: | :---: | :---: |
| 10 | 20 | 0 | 1 | 0 |
| 20 | 10 | 0 | 0 | 0 |
| 10 | 10 | 1 | 0 | 0 |
| 0 | -10 | 0 | 0 | 0 |
| -10 | 0 | 0 | 1 | 0 |
| 0x7FFFFFFFFFFFFFFF | -1 | 0 | 1 | 1 |

### 5. 분기 명령어

분기 명령어는 명령어 포인터(RIP)를 바꿔 프로그램의 실행 흐름을 전환한다.

```nasm
jmp <label>      ; 조건 없이 지정된 주소로 무조건 점프
je  <label>      ; jmp if equal  (ZF == 1)
jz  <label>      ; jmp if zero   (je와 동일 기능)
jne <label>      ; not if equal  (직전 비교가 다르면 점프)
jnz <label>      ; not if zero   (jne와 동일 기능)
jg  <label>      ; ZF==0 && SF==OF 일 때 점프 (왼쪽 피연산자가 더 큼)
jge <label>      ; SF==OF 일 때 점프
jl  <label>      ; SF!=OF 일 때 점프 (왼쪽 피연산자가 더 작음)
jle <label>      ; ZF==1 || SF!=OF 일 때 점프
```
{: file="branch.nasm"}

`label`은 특정 주소에 이름을 붙인 기호로, 코드 규모가 커질 때 특정 지점을 분리해서 참조할 수 있게 해준다.

### 6. 반복문 구현 패턴

어셈블리어에는 별도의 반복문 키워드가 없고, 분기 명령어 조합으로 세 가지 형태를 구현한다.

* **카운터 기반**: 반복 횟수를 정해두고 그 횟수만큼 반복
* **조건 기반**: 특정 조건이 만족될 때까지 반복
* **후조건 검사**: 명령어를 먼저 실행한 뒤 조건을 검사(최소 1회 실행 보장)

## 요약

* **본질**: x64 어셈블리는 명령어 + 피연산자 구조이며, 문법 표기는 AT&T(GAS)와 Intel(NASM) 두 방식이 대표적이다.
* **핵심 포인트**: `mov`는 값을 읽고 `lea`는 주소를 계산한다는 차이, `cmp`(뺄셈)와 `test`(AND)가 플래그를 갱신하는 방식의 차이, `mul`/`div`가 결과를 여러 레지스터에 나눠 저장한다는 점이 헷갈리기 쉬운 핵심 포인트다.

## 코드 해석 팁

x64 환경은 **리틀 엔디언**을 사용하므로 `0x123456` 같은 값은 메모리상에서 `56 34 12` 순서로 저장된다는 점을 항상 염두에 둬야 한다.

디스어셈블된 코드를 해석할 때는 처음부터 모든 값을 하나하나 노가다로 계산하기보다, **우선 코드의 흐름을 먼저 파악**하고 그 다음에 스택 구조를 머릿속으로(또는 필요하다면 직접 그려서) 그려보는 방식이 훨씬 효율적이다. 특히 스택 구조가 복잡하거나 크기가 커질수록 직접 그려보는 습관이 도움이 된다.
