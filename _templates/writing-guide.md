# 글쓰기 가이드

> 이 파일은 `_templates/` 폴더에 있어서 **사이트에 올라가지 않는다.** 글을 쓸 때 옆에 열어 두는 용도이다.
> 기준은 지금까지 쓴 글, 특히 `double-DES`, `Squared Flag`, `RSA 정리`, `암호분석경진대회` 글이다.
> 새 글부터 이 기준을 따른다. **예전 글은 일부러 고치지 않는다.** 글 파일 이름(주소)은 바꾸지 않고, 글을 새로 쓰거나 크게 손볼 때만 맞춘다. (이미지 폴더는 이미 아래 구조로 정리했다.)
> 아래 섹션 이름은 기존 글에서 흔한 이름을 하나로 통일한 것이다. 예를 들어 마무리는 글마다 `요약`과 `정리`가 섞여 있는데, 새 글에서는 `정리`로 쓴다.

## 새 글 만드는 순서

1. `_posts/YYYY-MM-DD-영문-슬러그.md` 파일을 만든다. 슬러그가 그대로 주소가 된다. (`2026-10-15-RSA-summary.md` → `/posts/RSA-summary/`) 공백 없이 영문으로 짧게 쓴다.
2. 이미지는 `assets/img/posts/카테고리/분야/글/` 폴더에 넣는다. 예: `assets/img/posts/ctf/crypto/double-des/` ([이미지 폴더와 이름](#이미지-폴더와-이름) 참고)
3. 아래 [유형별 구조](#유형별-구조)에서 맞는 뼈대를 복사해 붙이고 채운다.
4. `bundle exec jekyll serve`로 `http://127.0.0.1:4000`에서 확인한다.
5. 점검표(맨 아래)를 확인하고 커밋한다.

## 공통 규칙

### 한 글, 한 목적

- 한 글은 한 가지 일만 한다. 개념을 설명하는 글, 해 본 과정을 남기는 글, 문제를 푸는 글을 한 글에 섞지 않는다.
- 설명이 길어지면 개념 정리 글로 떼어 내고 링크한다. (풀이 글에서 RSA를 길게 설명하지 않고 [RSA 정리](/posts/RSA-summary/)로 보낸다.)
- 맨 위 몇 줄(`description`과 `prompt-info`)만 읽어도 무엇을 다루는지 알 수 있게 쓴다.

### front matter

```yaml
---
title: "double-DES"
date: 2026-10-01
categories: ['CTF/Wargame']
tags: [Dreamhack, Crypto, DES, Meet-in-the-Middle]
description: double-DES 풀이 - 이중 DES 키 탐색을 Meet-in-the-Middle로 줄여 flag를 얻는다
math: true          # 수식($$ ... $$)을 쓸 때만
---
```

| 항목 | 규칙 |
|---|---|
| `title` | 짧게. 문제 이름이나 주제만 쓴다. (`double-DES`, `RSA 정리`) 설명은 `description`에 쓴다. 대회 글은 `암호분석경진대회 · 7번 소인수분해`처럼 `대회 · 문제` 형태로 쓴다. |
| `date` | `2026-10-01`처럼 날짜만 쓴다. 같은 날 쓴 글의 앞뒤 순서를 정하고 싶을 때만 `2026-10-11 21:00:00 +0900`처럼 시간을 붙인다. 이전/다음 글 링크가 이 순서를 따른다. |
| `categories` | **하나만.** `_data/categories.yml`의 `name`과 글자까지 똑같이 쓴다. 다르면 분야 목록에 나타나지 않는다. |
| `tags` | 플랫폼 → 분야 → 기법 순. (`Dreamhack, Crypto, DES, Meet-in-the-Middle`) 이미 있는 태그는 Tags 페이지에서 철자와 대소문자를 확인하고 맞춘다. |
| `description` | 한 문장. 워게임은 `문제 이름 풀이 - 한 줄 요약`, 개념 글은 무엇을 알 수 있는지. 검색 결과와 링크 미리보기에 쓰인다. |
| `math` | 수식을 쓸 때만 `math: true`. 쓰지 않는 글에는 넣지 않는다. (수식 라이브러리를 불러오지 않아 더 빠르다) |
| `image` | 쓰지 않는다. 표지(썸네일)는 이 사이트 화면에 나오지 않아서 넣지 않는다. 링크 미리보기에는 이미지가 붙지 않는다. |
| `featured`, `summary` | 홈의 "대표 글"에 올릴 때만. [아래](#홈-화면에-쓰이는-값) 참고. |

### 이미지 폴더와 이름

```text
assets/img/posts/<카테고리>/<분야>/<글>/<파일>
예) assets/img/posts/ctf/crypto/double-des/flag.png
```

| 카테고리 폴더 | 글의 카테고리 | 분야 폴더 |
|---|---|---|
| `ctf` | CTF/Wargame | `web` `system` `reversing` `crypto` |
| `notes` | 블로그/기술문서 | `system` `reversing` `network` `crypto` `web` `tools` |
| `contest` | 공모전/자격증 | 분야 대신 대회 이름 (`crypto-analysis-2026`) |
| `misc` | 잡동사니 | `math`(수학 정리) `etc`(그 밖의 글) |
| `paper` `bug-bounty` `dev` | 논문/컨퍼런스, Bug Bounty, 개발 | 첫 글을 올릴 때 만든다 |

- 글 폴더 이름은 글 파일 이름에서 날짜를 뺀 슬러그를 소문자와 하이픈으로 쓴다. (`2026-10-06-Squaredflag.md` → `squared-flag/`)
- 폴더와 파일 이름은 영문 소문자, 숫자, 하이픈만 쓴다. 한글·대문자·밑줄·공백은 쓰지 않는다. (`libc-pop-rdi.png`, `caesar-bruteforce.png`)
- 이미지가 없는 글은 폴더를 만들지 않는다.
- 같은 주제의 글이 여러 편이면 묶음 폴더를 만들고 그 안에 글 폴더를 둔다. (`ctf/system/bof/bof-00/`, `ctf/web/sqli/sqli-waf/`) 두 글 이상이 같은 이미지를 쓰면 두 글을 묶는 폴더에 둔다. (`contest/crypto-analysis-2026/classic-cipher/`)
- 사이트 공용 이미지(프로필, 파비콘)는 `assets/img/site/`에 둔다.
- 표지(썸네일)는 쓰지 않는다. 본문에 필요한 이미지만 올린다.
- 스크린샷에 사용자 이름, 경로, 토큰이 보이면 가리고 올린다.

### 문체와 표기

- 문체는 `~이다/~한다`로 통일한다. `~함/~있음`, `~합니다`를 섞지 않는다.
- 용어는 처음 등장할 때 `한글(English)` 형태로 쓰고 코드 스팬으로 강조한다. 이후에는 한쪽으로 통일한다.
- 띄어쓰기를 확인한다. "~할 수 있다", "~한 뒤", "예를 들어"
- 한 문단은 3~4문장 안으로 쓴다. 길어지면 목록이나 표로 바꾼다.

### 헤딩

- `#`은 쓰지 않는다. 글 제목이 이미 `#`이다.
- `##` → `###` → `####` 순서로 쓰고 레벨을 건너뛰지 않는다.
- 왼쪽 목차에는 `##`와 `###`만 나온다. 찾아볼 만한 항목은 `###`까지 올린다. 목차는 `##`와 `###`가 합쳐 2개 이상일 때 생긴다.
- 번호가 의미 있는 단계는 `### 1. 소인수분해 공격`처럼 번호를 붙인다.

### 본문 요소

````markdown
> 핵심 요약이나 정의
{: .prompt-info }
````

- **콜아웃**: `prompt-info`(핵심 요약·정의), `prompt-tip`(보충·팁), `prompt-warning`(주의·한계), `prompt-danger`(위험). 한 글에 3개 안팎으로 쓴다. 닫는 줄 `{: .prompt-info }`는 인용문 바로 다음 줄에 붙인다.
- **코드**: 언어를 꼭 적는다. 파일 이름을 보이려면 코드 블록 바로 아래 줄에 `{: file="main.py" }`를 쓴다. 줄 번호와 복사 버튼은 자동으로 붙는다. 긴 코드는 핵심 부분만 싣는다.
- **표**: 머리글 줄은 필수. 화면보다 넓으면 알아서 가로 스크롤이 된다.
- **이미지**: `![설명](/assets/img/posts/ctf/crypto/double-des/flag.png)` 바로 다음 줄에 `*캡션*`을 쓰면 가운데 작은 글씨 캡션이 된다. 설명(alt)은 비우지 않는다.
- **수식**: `math: true`를 켠 뒤 `$$ N = pq $$`로 쓴다. 한 줄을 차지하게 하려면 앞뒤를 빈 줄로 띄운다.
- **각주**: 본문에 `[^1]`, 글 끝에 `[^1]: 설명`. 글 끝에 모여 나온다.
- **다른 글 링크**: `[RSA 정리](/posts/RSA-summary/)`처럼 `/posts/슬러그/`로 쓴다.
- **구분선** `---`은 `## 참고 자료` 바로 앞에서만 쓴다.
- 다이어그램(`mermaid`)은 이 사이트에서 지원하지 않는다. 그림으로 만들어 이미지로 올린다.

## 유형별 구조

### 1. 워게임/CTF 풀이

문제 하나를 풀고 **왜 되는지**까지 남기는 글이다. 새 글은 아래 구조로 쓴다. (2026-06~07의 초기 글은 `Concept / 서비스 분석 / 익스플로잇` 3단이다. 그대로 둔다.)

| 섹션 | 쓰는 내용 |
|---|---|
| `## 문제 정보` | 표(플랫폼·분류·난이도·풀이일·취약점·공격 유형·핵심 기법)와 `prompt-info`로 **한 줄 요약**. |
| `## 문제 설명` | 문제가 무엇을 하는지 2~3문장. 제공 파일과 목표를 목록으로. |
| `## 분석` | `### 코드 분석`(핵심 코드만), `### 취약점`(왜 뚫리는지). 보호 기법이 있으면 `### 보호 기법`. |
| `## 공격 시나리오` | 번호 목록 3~5단계. 분석에서 익스플로잇으로 넘어가는 다리이다. |
| `## 익스플로잇` | `### 핵심 아이디어`, `### 익스플로잇 코드`(`file=` 사용), `### 실행 결과`. |
| `## 정리` | `### 핵심 요약`(번호 3개 안팎), `### 배운 점`. 필요하면 `### 방어 방법`. |
| `## 참고 자료` | 앞에 `---`. 문제 링크, 문서, 논문. |

**분야별로 달라지는 부분**

| 분야 | 분석에서 다룰 것 | 익스플로잇에서 다룰 것 |
|---|---|---|
| 웹 | `### 서비스 분석`: 엔드포인트와 기능, 입력이 어디로 가는지(Source → Sink) | 요청과 페이로드, 결과 화면 |
| 시스템(pwn) | 취약점 발생 원인, 메모리 구조와의 관계, 보호 기법(canary, NX, ASLR) | `### 오프셋 계산`, `### 로컬 테스트`, 익스플로잇 스크립트 |
| 리버싱 | `### main` → `### 검증 함수` → `### 비교 대상 데이터` 순서로 따라간다 | `### 역연산 도출`, 스크립트, 입력해 본 결과 |
| 암호 | 키 구조, 암·복호화 순서, 알려진 평문이나 힌트, **전수조사가 안 되는 이유**(복잡도) | 핵심 아이디어 → 수식 → 코드. 수식이 있으면 `math: true` |

**쓸 때 지킬 점**

- 취약점 개념을 처음 다루면 `## 문제 설명` 앞에 `## 배경 지식`을 두고 짧게 설명한다. 이미 쓴 글이 있으면 링크로 대신한다.
- 풀이를 공개해도 되는지는 플랫폼·대회 규정을 확인한다. 진행 중인 대회 문제는 끝난 뒤에 올린다. flag를 그대로 보일지는 글쓴이가 정하고, 토큰·비밀번호 같은 개인 정보는 가린다.
- 익스플로잇 코드는 조각으로 나누지 말고, 입력부터 flag 출력까지 한 번에 도는 완전한 스크립트 하나로 싣는다. 설명에 필요한 조각은 `분석`에서 따로 보인다.
- 풀이 과정에서 막혔던 부분(틀린 시도)도 한두 줄 남긴다. 나중에 가장 쓸모 있다.

### 2. 개념 정리

개념 하나를 **처음 보는 사람도 따라올 수 있게** 설명하는 글이다. 나중에 내가 다시 찾아볼 때 가장 많이 쓰인다.

| 섹션 | 쓰는 내용 |
|---|---|
| `## 개요` | 무엇이고 왜 알아야 하는지 2~3문장. 이전 글이 있으면 어디서 이어지는지 한 줄. `prompt-info`로 핵심 한 줄. |

### 5. 책·강의 정리

책이나 강의를 읽고 **내 말로 정리**하는 글이다.

- 맨 위에 출처를 한 줄로 쓴다. (책 이름, 장, 강의 이름)
- 원문 문장과 그림을 그대로 옮기지 않고 내 말로 요약한다.
- 개념마다 같은 틀을 반복한다: `### What is X?` → `### 취약점이 발생하는 과정` → `### Impact` → `### Mitigation` (`OS 커맨드 인젝션 & XSS`를 참고한다.)
- `description`에는 `크리핵티브 5, 6장 정리`처럼 출처와 범위를 쓴다.
- 마지막에 내가 직접 해 본 것이나 다른 글과의 연결을 한 문단 쓴다.

### 6. 논문·컨퍼런스 리뷰 (아직 쓴 글 없음)

제안하는 구조이다. 첫 글을 쓰면서 다듬는다.

1. `## 논문 정보` — 표(제목·저자·학회와 연도·링크)와 `prompt-info`로 한 줄 요약. 이어서 5C를 한 줄씩 답한다: Category(어떤 종류의 논문인가), Context(어떤 연구 위에 서 있는가), Correctness(가정이 타당한가), Contributions(기여가 무엇인가), Clarity(잘 쓰였는가)
2. `## 문제의식` — 이 논문이 풀려는 문제와 기존 방법의 한계
3. `## 핵심 아이디어` — 방법을 내 말로. 그림이나 수식 포함
4. `## 결과` — 무엇을 어떻게 비교했고 어떤 수치가 나왔는지
5. `## 내 생각` — 한계, 적용해 볼 수 있는 곳, 이해하지 못한 부분
6. `## 참고 자료`

### 7. 버그 바운티 (아직 쓴 글 없음)

제안하는 구조이다. **프로그램 정책이 공개를 허용한 내용만 쓴다.** 수정되기 전의 취약점이나 비공개 프로그램은 올리지 않는다.

1. `## 요약` — 대상(공개 가능한 범위), 취약점 유형, 심각도, 처리 상태를 표로
2. `## 발견 과정` — 어떻게 찾았는지, 어떤 생각으로 접근했는지
3. `## 원인` — 왜 취약했는지
4. `## 재현 방법` — 번호 단계. 필요한 권한·URL·파라미터를 쓰고, 실제 서비스에 영향을 주는 값은 가린다. 끝에 **기대한 동작과 실제 동작**을 한 줄씩 대비한다
5. `## 영향과 대응` — 공격자가 얻는 것(Impact), 패치나 완화 방안(선택)
6. `## 타임라인` — 제보 → 응답 → 수정 → 공개 날짜

카테고리는 `잡동사니`를 쓰고, 이미지는 `assets/img/posts/misc/math/글/`에 둔다. 주제는 태그로 나눈다.

| 섹션 | 쓰는 내용 |
|---|---|
| `## 개요` | 무엇을 다루고 왜 필요한지 2~3문장. 선수 지식은 링크로. `prompt-info`로 핵심 한 줄. |

| `## 예제` | 작은 수로 직접 계산한다. 빠뜨리지 않는다. |

**쓸 때 지킬 점**

- `math: true`를 켜고 수식은 `$$ ... $$`로 쓴다.
- 정의·정리·보조정리·따름정리는 `**정의 1 (이름).**`, `**정리 2 (이름).**`처럼 굵게 시작하고, 번호는 글마다 새로 매긴다. 증명은 `**증명.**`으로 시작해 `∎`로 끝낸다.
- 증명을 아직 이해하지 못했으면 억지로 쓰지 않는다. "증명은 교재 §n 참고"라고 쓰고 아이디어만 적은 뒤, 나중에 채운다.
- 교재의 문장과 증명을 그대로 옮기지 않고 내 말로 쓴다. 출처는 책 이름과 장·절로 남긴다. ([책·강의 정리](#5-책강의-정리)와 같은 규칙)
- 한 글에는 개념 하나만 다룬다. 선수 관계가 있으면 링크로 잇는다. (합동식 → 오일러 정리 → [RSA 정리](/posts/RSA-summary/))
- 태그는 영문으로 쓴다. 맨 앞에 `Math`를 붙이고 주제를 잇는다. (`Math, Number-Theory, Crypto`)

## 홈 화면에 쓰이는 값

| 바꾸려는 것 | 고치는 곳 |
|---|---|
| 홈 대표 글 (최대 3개) | 글 front matter에 `featured: 1`(숫자가 작을수록 앞), `summary: 카드에 보일 한 문장` |
| 홈 "Now" 카드 | `_data/now.yml` |
| 홈 "기록" (자격증·수상·활동) | `_data/records.yml` (항목이 없으면 구역이 사라진다) |
| 카테고리 순서와 설명 | `_data/categories.yml` (글이 없는 카테고리도 0으로 표시되고, 글을 쓰면 자동으로 링크가 생겨 위로 올라간다. 새 카테고리는 여기에 먼저 추가한다) |
| 홈 첫 문구 | `index.html`의 front matter |
| About 소개·관심 분야·이력 | `about.md`의 front matter |

## 올리기 전 점검

- [ ] `categories`가 `_data/categories.yml`의 이름과 같은가
- [ ] `description`을 한 문장으로 썼는가
- [ ] 수식을 썼다면 `math: true`를 켰는가 (안 썼다면 껐는가)
- [ ] 문체가 `~이다/~한다`로 통일되어 있는가
- [ ] 헤딩 레벨을 건너뛰지 않았는가
- [ ] 코드 블록마다 언어를 적었는가
- [ ] 이미지를 `posts/카테고리/분야/글/`에 영문 소문자-하이픈 이름으로 넣었고, 경로가 맞고 설명(alt)이 비어 있지 않은가
- [ ] 스크린샷에 사용자 이름·경로·토큰이 보이지 않는가
- [ ] 풀이 공개 규정을 확인했고, 토큰·비밀번호 같은 개인 정보가 노출되어 있지 않은가
- [ ] 수치·수식·출처를 다시 확인했는가
- [ ] 오탈자와 띄어쓰기를 확인했는가
- [ ] `bundle exec jekyll serve`로 화면에서 확인했는가
